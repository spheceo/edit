# Agent notes

## Git commits

Never add a `Co-authored-by` trailer (Cursor, agents, or otherwise). Commit as the user only: `git add`, `git commit`, and `git push` with a normal message body — no co-authors, no extra attribution trailers.

## Layout

- `crates/edit-core` — project model and frame evaluation. Pure Rust, no I/O; compiles natively and to WASM. Timeline times are integer frames; `source_in` is seconds. `Project::validate` is the contract every writer (UI, MCP) must satisfy.
- `crates/edit-render` — the wgpu compositor. The browser preview and the export both call `Renderer::render`; never add an effect to only one side. Shaders live in `src/shaders/`.
- `crates/edit-wasm` — wasm-bindgen wrapper; `just wasm` writes `apps/web/src/engine/pkg` (generated, gitignored).
- `crates/edit` — `edit` / `edit app` opens the editor in a Tauri window (`app.rs`, the `app` feature, on by default: the same server runs in-process and the window loads `http://127.0.0.1:7700`, so everything below works unchanged; links out open in the browser; WKWebView has no `window.confirm`/`alert`, so don't use them in the UI, and its WebGPU validates more strictly than Chrome's: a viewport outside the target drops the whole frame). `edit serve` is the same thing headless: REST + websocket events, FFmpeg media jobs, native frame renders, export, MCP at `/mcp` (`?project=` scopes a connection to one project), and `agent.rs`, the Codex app-server bridge behind the agent panel.
- `assets/sfx/` — sound effects compiled into the `edit` binary (`crates/edit/src/sfx.rs`), so every install has them; written on first use to `~/.edit/sfx/<name>-<hash>.wav` (a new version is a new file, so old projects keep theirs). Each ships with a "hit" marker (media markers) that `add_sound_effect` lines up on the cut. `shutter.wav` is the first shutter from https://youtu.be/R24UqkKj90w, trimmed to 0.17 s.
- `crates/edit/src/library.rs` — the team's sound library: the "Music & SFX Library" folder in Google Drive is the source of truth (a folder per category under Music / Sound effects, plus an index .txt of per-file notes and a usage-guide Doc). Edit lists it through the Drive API and downloads a sound on first use to `~/.edit/library/<music|sfx>/<checksum>/`; nothing is bundled. It needs `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET` and `GOOGLE_DOCS_REFRESH_TOKEN`; while testing, `just dev` borrows Repack's from Infisical (only those three). The UI's Library tab and the agent's `list_library` / `add_from_library` use it. One download per file at a time (a second ask waits for it); curl gives up on a stalled one, so it's retried rather than held forever.
- `crates/edit/src/loudness.rs` — every measurement of sound (`library::levels` / `loudness`: `measure_audio`, `set_loudness`, `add_from_library`'s `loudness` and `under_speech`, voice-over levels) is arithmetic over the file's analysis: one FFmpeg decode makes 10 ms blocks of K-weighted energy and sample peak, kept as `<cache>/<media key>/loudness-v1.bin` (the media key covers size and mtime, so a changed file is analysed again) and in memory. It matches FFmpeg's `ebur128` (padded with 0.5 s of silence) within 0.5 LU (`matches_ffmpeg_ebur128`); a new method or layout is a new file version. Imports analyse in the background; `prepare` analyses several files three at a time. `library::footage_loudness` is the edit's speech (the footage's sound, else its voice-overs), what `under_speech` counts down from.
- `crates/edit/src/cutin.rs` — `cover_cut_in`: the agent picks a cut-in's B-roll shots and this lays them out the house way in one call (butted shots, push-ins, B-roll look, vertical drop, card gone, voice-over to A1). Slowed clips use native frame sampling; optical flow is opt-in (`smooth: true`), serialized with other background media work and limited to 120 seconds per shot. Exports take the current timeline snapshot immediately unless `wait_for_smoothing` is explicitly requested.
- `crates/edit/src/broll.rs` — `map_view` renders the map page in headless Chrome (one at a time). A moving shot answers once its first frame and building track are in and renders the rest in the background: the media is that first frame (`map-<key>-first.jpg`) until the footage swaps in under the same media id. Frames land whole on disk, so a render cut short carries on from them when `map_view` is called again with the same arguments. Exports wait for a map still rendering (the agent's up to 10 minutes, the UI's a few seconds) and refuse a stand-in on the timeline whose render failed or was cut short, saying so; they never export the still by mistake. `track_region` (`track.rs`) template-matches small greyscale frames (the box ~40 px wide; the light preview when frames are looked at ≤640 wide, else the original, so a small face in a zoomed-in shot isn't blurred by the preview; AVFoundation on macOS, FFmpeg otherwise) at the footage's rate for stretches up to 40 s, 15 fps beyond; each frame the box is first carried by the camera's move (`motion.rs`: shift, turn and zoom fitted to a grid of patches, cuts detected), searched coarse to fine to a fraction of a pixel with a centre-weighted template (less weight on the wall behind a face), held to the box as given against drift, lost when matches are weak (it rides with the camera; reported), looked for anywhere after a cut (confirmed by the next frame). `boxes` adds sightings: passes run from each to the next, their drift is spread back so they meet each sighting, and they're blended; the path is smoothed by a centred local line fit (no lag), never across a cut. Positions go through the footage's keyframed framing (a push-in), which the static transform missed. Frames are kept a few minutes for another pass; coordinates stay in source pixels. `real_bench_face` (ignored; `EDIT_TRACK_REAL`) measures it on Mom & Teen's bench shot.
- `crates/edit/src/edit_plan.rs` — `apply_edit_plan` applies a whole stage in memory (times in frames; `add` needs start and duration; `transition`, `evidence_board`, `evidence_card`, `date_title` and `place_label` build house graphics in one line (`graphics.rs` has the last three: the date cut-in's date is white with only a drop shadow over a darkening adjustment, never boxed or glowing; the map's place label is the house label pinned to `building_track`; an evidence card is one picture framed over a dark blurred copy of itself with its label, and `cover_cut_in` lays every picture shot out as one, so a found photo is never plain B-roll): an evidence board is framed photos (video clips' `frame`: border and drop shadow) on paper, the camera in one continuous glide past them (each photo centred at its `at`, the frame of the word naming it; a smooth S whose speed eases to ~70% of its average at each photo and picks up between, never stopping) and red notes in Reenie Beanie writing on; each photo's `at` is marked ("board photo") and gets a quiet bundled shutter whose click lands on it, unless `shutters: false` or another shutter is within 8 frames; `desktop_profile` is the profile screen for a person whose only picture is a still (`desktop.rs`); `markers` as the markers tool; moving or deleting one half of a linked pair takes the other along unless `unlinked`), resolves named references, validates the final project and commits once with `base_rev`; an invalid/stale plan saves nothing. Its `audit` is the mechanical review (picture gaps, slivers, bare cut-in cards, exhausted sources, misaligned linked sound, review notes like "[unclear]" left in on-screen text, the same B-roll moment in two places, transitions with no sound, a subtitle past its cut, footage under 8 frames, a picture on screen outside a designed graphic (`bare_still`, `letterboxed`), a boxed or glowing date (`date_style`); and, where the MCP side adds what needs the media cache: B-roll that's mostly pixelated or blurred, `censored_broll`, and quote callouts off the words that point to them, `callout_off_speech`, from `edit_review::callout_timing`), so the agent renders only for judgement. The plan's house pictures and sounds (the board shutter, the desktop's wallpaper and windows) are added to the plan's own copy of the project first (`mcp::plan_assets`, `server::house_media`), so it still saves once or not at all. A plan that adds or relabels text ends with `people::one_colour_per_person`. Begin with `get_edit_context`: one line per clip, cut-in words as `word@seconds`, narrowed by `section` (intro / story / outro) or start/end, capped near 36k characters (Codex truncates tool output at ~10k tokens). `find_in_footage` (`footage_search.rs`) searches every footage transcript for many phrases in one call (B-roll candidates). `batch` runs independent lookups three at a time.
- `crates/edit/src/desktop.rs` — `desktop_profile`: a person's photo in a dark Photo Viewer window and lines about them typed (word by word) into a Notepad window, on a blue light-beam desktop, the windows scaling up from 96% one after the other, a slow push-in over the screen, the windows leaving over the last 8 frames. The wallpaper (a drawn lookalike: gradients and soft beams, nothing of Microsoft's) and the window frames (title, menus and buttons rasterised with the bundled Geist through `edit_render::text`) are PNGs Edit draws itself into `~/.edit/graphics/` per size and title (`VERSION` in the name: a new look is a new file); the photo, the lines and the film grade are ordinary clips, so preview and export draw it alike. Layout measured off the team's reference frame at 1080p. `desktop::tests::render_a_profile` (ignored; `DESKTOP_PHOTO`, `DESKTOP_OUT`) renders frames for eyeballing.
- `crates/edit/src/markers.rs` — marked moments to plan sounds on: on a media at source seconds (`Marker {time, name, note}`, so they move with every clip of that moment) or on the timeline (`Project::markers`, frames, carried by ripples). The `markers` tool / plan op adds, removes and lists them; `add_sound_effect` / `add_from_library` take `markers: [name]`; `get_edit_context` lists them in its span. A sound's own "hit" is never listed or removed by name alone. The ruler shows timeline markers as amber flags.
- `crates/edit/src/censor.rs` — redacted footage: each file read once (the light preview's keyframes, a 128×72 grey frame a second; one at a time in the background, started by the audit) and every second judged by how flat it is (≥78% of neighbouring pixels within 2 levels, mean difference ≤3.5, contrast kept); `<cache>/<media key>/censor-v1.bin`, one byte a second. B-roll with ≥60% of its seconds censored is `censored_broll`; files not read yet are `censor_check_pending`. `censor::tests::audit_a_real_project` (ignored) audits a real project read-only.
- `crates/edit/src/mac_media.m` / `mac_media.rs` — macOS AVFoundation video and sound readers, bounded pixel-buffer writers and an AAC writer, ImageIO still-image decoding and encoding (JPEG for agents), and Accelerate pixel conversion and scaling. Standard hardware H.264/HEVC exports and preview video transcoding use them; the compositor is still `edit-render`. FFmpeg handles nonstandard export options, other speeds' sound (atempo), explicit optical flow, and compatibility decoding. `EDIT_FFMPEG_VIDEO=1` / `EDIT_FFMPEG_AUDIO=1` select the compatibility backends for diagnosis. Photos stay images on macOS; do not encode them into 30-second videos.
- Exports (`render.rs`): the sound is mixed first in Rust (`mix.rs`: each clip's stretch decoded on its own, a few seconds' window at a time; loudness: the gain that reaches the target, measured again after a look-ahead limiter that holds peaks under -1 dBTP), then the picture runs as a pipeline (planner → three decoder threads, one reader each, jump cuts sent to the one already in that file → compositor with readbacks in flight → encoder thread), and FFmpeg joins picture, sound and chapters without re-encoding. Don't run AVFoundation sound reads beside the picture's decoders: they contend (~30× slower). Frames stay BGRA from decoder to GPU. The log line "frames composited in …; waited … on decoding, … on encoding" says which stage limits an export. Agent renders (`render_for_agent`) go ahead of the UI's, decode a sheet's pictures side by side at the size shown, and return JPEG.
- `crates/edit/src/skills.rs` — the house style beyond the core (`mcp::INSTRUCTIONS`, which lists the skills), loaded by the agent with the `skill` tool when it reaches that part of the edit: edit-workflow, research, intro, transitions, cut-ins, outro, subtitles, subtitle-video, music-and-sound, final-pass. There's no Full edit button: the user says "start the editing workflow" (plus any steering) in the chat, and the agent loads edit-workflow and does the whole edit in that one turn, stage by stage; loading it also starts `watch_footage` in the background. What made full edits take hours was model round trips, not tools: a conversation 200k+ tokens long (each answer several times slower; Edit's Codex threads now compact at 150k), the agent polling slow tools second by second in Codex's code mode, and checking the same work again and again. So the developer instructions (which also carry `mcp::tool_reference()`, every tool on one line, so code mode needn't look them up), the core and the skills ask for one context read, one plan, one look per stage; keep it that way when adding rules: say what to check, never "check with render_frame". A new rule goes in the skill for its part; only what every part needs goes in the core.
- `crates/edit/src/watch.rs` — the watcher for subtitled videos (`watch_footage`, `POST /api/projects/{id}/watch`): Gemini watches the footage about four minutes at a time with sound (small 360p 1 fps MP4s: Gemini samples video at 1 fps; cut from the light preview's keyframes and its AAC sound when the media has them, else from the original; all windows at once, low reasoning, which answers a window in ~40 s instead of ~100 s with the same speakers; one watch per project at a time, so a second waits and reads the cache; transcripts fetched side by side; its report lists the lines it only guessed, `doubtful`), says who speaks each subtitle line (corrections are written into the transcript's speakers, so `repack_subtitles` and `add_subtitles` use them) and, only for a subtitled video (`watch::sets_segments`), marks the project's segments; on an edit it watches each stretch of each file the clips use, once. Both subtitlers share `subtitles::house_words` (mutes + starring); `mute_house_words` applies just that to subtitles finished by hand. Its mutes reach the voice-overs too (`voiceover::voiceover_sound`, from the takes' cached transcripts), so the narration never says a word starred on screen. Answers are cached per window in the media's cache dir (`watch/`). It calls the Vercel AI Gateway with `AI_GATEWAY_API_KEY` from the environment (`just dev` borrows it); for production it should move behind the relay like the other paid calls.
- Speaker colours (`speakers.rs`): each transcript picks its voices' colours by role (Repack's code); `speakers::distinct` then keeps people apart across files in both subtitlers (who says most keeps their colour; `add_subtitles` per label), and officers, leaders and dispatch never get pink or magenta (`speakers::pinkish`), which go to civilians.
- `crates/edit/src/seats.rs` — Repack's positional subtitles for interrogations (`repack_subtitles` with `overlap`, `faces` on by default): camera angles from 64×36 greyscale frames (a cut is a jump between frames; a long scene is an angle, and later stretches that look the same, however short, are that angle), then per angle Gemini watches up to two 90 s stretches with sound and a still (every angle's stretches eight at a time; one after another took 18 minutes) and gives each named speaker's face box; the medians are cached as `seats-v2.json` in the media's cache dir. `subtitles::under_face` lays a line out the way Repack's `subtitleLayout` does (80 px under the face, 28–40% wide, beside the face toward the middle when it would leave the frame, bottom middle for a bottom-corner face), and overlaps stack vertically only where boxes collide.
- `crates/edit/src/faces.rs` — subtitles never cover a face: Apple's Vision face detector (`mac_media::faces`) on 640-wide frames of the light preview, two a second of source, only where subtitles are up, cached per file as `faces-v1.json` in the media's cache dir (a 30-minute edit's first run takes a minute or two; later runs and other projects on the same footage read it back; off macOS nothing is found). `place_subtitles` (run by `add_subtitles` and as its own tool) keeps each labelled subtitle bottom middle unless a face seen while it's up would be under it (the face grown to take in hair and chin), then the first clear of bottom left, bottom right, top middle/left/right (below the top band where bodycam stamps sit), the least covered when none is; a line stays where the one just before it moved while the face is still near, so conversations don't jump. Only Edit's own places count as unmoved (`placed_by_edit`): hand-moved or keyframed subtitles are left alone and kept by re-runs. Blurs and redaction boxes aren't faces; subtitled (Repack) videos keep Repack's places. Intro speaker captions (`captions::lay_out`, used by `caption_speakers` and `place_captions`): the model (Luna) only says who speaks; the face detector says where: the Vision face its box means (`faces::pick`, none for a hand or object), followed sample to sample by nearest face of like size (`faces::follow`, no template matching), and only when clearly visible (found in 3 of 4 samples, at least 7% of the picture tall) does the caption sit under it, smoothed, still when the face hardly moves, clear of every grown face and the top band; else bottom middle (0.36 of the height) or the first spot clear of faces. `place_captions` re-lays existing captions (`under`: per clip a point on the speaker's face, or bottom; default the face it already sat beside). A callout's leader (`track_region` target leader) follows a face the same way and refuses when there is none clearly visible (plain label then). The audit's `text_on_face` reads the cached faces.
- `crates/edit/src/people.rs` — one colour per person across the whole video, by construction: each person is a subtitle label ("Officer:"); their subtitle labels, their intro captions (matched through the transcript name in "Caption · <name>" / "Subtitle · <name>") and quotes named "Quote · <label>" get one colour from a 20-colour palette kept 28 ΔE apart (the role colours first; past the palette a minor speaker shares with whoever is furthest away in time). A person keeps their colour while it stands apart, so re-runs are stable and a colour chosen on purpose stays. It runs after `add_subtitles` (whose re-runs also keep each transcript voice's label and colour), `caption_speakers`, `update_clip(s)` touching a label, colour or name, and plans that add or relabel text; `get_edit_context`'s `speaker_line_counts` lists each label's lines, colour and the transcript voices it covers. The agent decides who is who (one label per person), never colours. White and near-white are never a person's colour. `subtitle_name` keeps a number ("Child 2" is not "Child"), and a relabel that puts a named voice under someone else's label is reported (`other_voices_under_this_label`). `watch_footage` drops a voice's name when most windows give that name to someone else (the transcriber named the mother "Kevin" from "I'm really worried, Kevin"), reported as `voices_renamed`; per-window answers can disagree, so only majorities count.
- `crates/edit/src/drive.rs` — a whole export of a subtitled video (`subtitles::is_subtitled`, MP4/MOV) is uploaded (Drive resumable upload through curl, with the library's sign-in) to the team's "Subtitles" folder (`12q4jbYhXI53BYZtTwOxzFEOJV2d1wJTk`, Repack's, where its renders go too; `EDIT_SUBTITLES_FOLDER` overrides), shared with anyone with the link; progress comes as `drive` events, and the project keeps the link (`project.drive`). `GET /api/projects/{id}/drive` checks the file is still on Drive (at most every 5 min) and clears the link when it was deleted or trashed; the UI calls it when it shows the link. Edit never deletes a Drive file; a re-export uploads a new one.
- `crates/edit/src/media_drive.rs` — the optional media drive, for a Mac whose own disk is too small: a folder (usually on an external drive) set in Settings → Media drive (`POST /api/media-drive`, saved in `<home>/settings.json`), `edit media use DIR`, or `EDIT_MEDIA_DIR` (overrides). Unset, everything is as before. Set, what Edit writes as media goes there, mirroring the data folder: `Store::drive_dir` / `uploads_dir` (Drive downloads and excerpts, uploads, voice-over takes sent to a project, stills, smoothed shots, map renders) become `<dir>/media/…`, and exports default to `<dir>/Exports`; projects and history, cache, library, sfx, research, voice projects, logs and settings stay in the data folder. Projects keep absolute paths: `Layout::resolve` (run as a project loads) finds a file on whichever side it is now (`media/…`, `uploads/…` under the data folder or any media folder ever set), and `media_key` names a file on the drive by its data-folder place (`Layout::key_path`), so previews, transcripts, loudness, watch answers and excerpt names survive a move that keeps sizes and mtimes. A drive that isn't connected (its `/Volumes/<name>` not a mount point, or no `.edit-media-drive` marker in the folder) is never written to: `drive_dir` / `uploads_dir` and exports into it return an error saying so (never a silent fallback to the full internal disk), and its files show as missing like any missing file; the home screen's setup card says it's unplugged. `edit media move --to DIR` (Edit quit: it refuses while a server holds `<home>/server.lock` or answers on `--port` with the same home) copies `media/` and `uploads/` there through `.edit-moving` files with mtimes kept, checks size and mtime, points projects at the copies through the store, and only then removes each original (checked again); interrupted, it carries on when run again, and a different file already at the destination is kept, never overwritten. Timed as `media: move` / `media: move file`.
- `apps/relay/` — Cloudflare Worker (`edit-relay`) that holds API keys (ElevenLabs transcription and voices; Google Maps for `map_view`, whose page in `crates/edit/src/map_page.html` loads 3D tiles through it) and rate-limits paid calls. Edit installs never get keys. Deploy from `apps/relay/` with `npx wrangler deploy` (wrangler is its dev dependency; `cf deploy` needs the config migrated to `cloudflare.config.ts` first, Durable Object included). Signed in only with `cf auth login`, wrangler can use that login: `CLOUDFLARE_API_TOKEN=<oauth_token from ~/Library/Preferences/cloudflare/config/default.json>`. The cloud token teammates paste in Settings → Cloud is `EDIT_CLOUD_TOKEN` in Infisical (the relay's `CLOUD_TOKEN`). Edit's Rust side reaches it through `crates/edit/src/relay.rs` (curl; `EDIT_RELAY_URL` for another relay, `EDIT_RELAY_TOKEN` sent as the bearer, token and JSON bodies through curl's stdin config, never argv).
- Cloud (`apps/relay/src/cloud.ts`, `crates/edit/src/cloud.rs`) — the foundation for cloud-shared projects: footage originals and preview proxies on R2, project files in Convex (the deployment shared with Repack; Edit's functions live in its `edit` module). The relay's `/v1/cloud/*` routes need `Authorization: Bearer <CLOUD_TOKEN>` (no IP fallback: unset or wrong is 401) and only touch R2 keys under `edit/` (no empty, `.` or `..` segments; the bucket is Repack's too) and Convex paths `edit:<name>`, adding `CONVEX_SERVICE_TOKEN` as `args.token`. R2 is reached with hand-rolled SigV4 presigned URLs (tested against AWS's example); Edit only ever gets those URLs. Worker secrets: `CLOUD_TOKEN`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `CONVEX_URL`, `CONVEX_SERVICE_TOKEN` (listed in `wrangler.toml`; dev values are in Infisical, `NEXT_PUBLIC_CONVEX_URL` is `CONVEX_URL`). `cloud.rs` is blocking (call from `spawn_blocking`): `presign`, `head`, `list`, `delete`, `upload_file` (one PUT under 64 MiB, else 64 MiB parts four at a time, each retried with a fresh URL, aborted on failure), `upload_stream` (any `Read`, 32 MiB parts two in flight, no temp file: Drive → R2 without touching the disk), `download` (resumes from `<dest>.partial` while `<dest>.partial.etag` matches; R2 ignores If-Range, so the ETag is what guards it), and `convex` / `query` / `mutation` (Convex's `{status, value | errorMessage}` as a `Result`). `edit cloud …` tries each by hand; `cargo test -p edit cloud::tests::live -- --ignored` runs a round trip against a real relay (e.g. `bunx wrangler dev` with `relay/.dev.vars`) under `edit/test/`.
- `crates/edit/src/cloud_projects.rs` — cloud projects. Cloud is on with a relay token (`EDIT_RELAY_TOKEN`, else the one pasted in Settings → Cloud, saved in `<home>/cloud.json`, mode 600, with the on/off switch) unless switched off; off, nothing changes. On, new projects are cloud projects (older ones get "Move to cloud"; their media follow through the backfill, see cloud_media.rs). Per project, `<home>/cloud/projects.json` keeps the cloud rev this copy is based on, whether it has unpushed changes, and its lock token. Saves land on disk as always; a background loop pushes ~2 s after the last change (upload the JSON, `edit:commitProject` with the base rev), retries with backoff offline, renews the lock every 45 s, lets it go when the editor closes (`POST …/cloud/close`), goes quiet (no editor heartbeat for 75 s, no write for 60 s) or Edit quits (`cloud_projects::shutdown`: Ctrl-C, window closed). Every write goes through `Store::commit` → `Cloud::may_write`: a project someone else holds is refused (HTTP 423, the agent gets the reason); one not asked about yet takes the lock first (blocking, once); unreachable, writes are allowed and queued. Losing the lock with unpushed changes, or a `conflict`, keeps this machine's version as "<name> (conflicted copy)" (local only) and takes the cloud's — never an overwrite. The editor calls `POST /api/projects/{id}/cloud/open` before loading (downloads a cloud-only project, then `cloud_media::ensure_local`), shows a read-only banner with Take over (force), and refreshes when the holder lets go. The holder label is `EDIT_CLOUD_HOLDER`, else the machine's name: keep it unique per machine (the same holder re-acquires without force). Two machines on one Mac: two `edit serve`s with their own `--home`, `--port` and `EDIT_CLOUD_HOLDER`.
- `crates/edit/src/cloud_media.rs` — cloud footage: big footage never sits on the Mac. With cloud on (`cloud::enabled()`), originals live on R2, every machine edits with a small proxy (`media.cloud` says where; `media.path` is this machine's copy), and exports read the originals; off, media work as before. Convex's footage registry (`edit:getMedia` / `listMedia` / `putMedia`) dedupes across projects and machines by source: `drive:<file id>`, `drive:<file id>#<start ms>-<end ms>` (an excerpt; start is its keyframe), `sha256:<hex>` (a file from a disk). Keys: `edit/originals/drive/<id>/<name>`, `edit/originals/sha256/<hex>/<name>`, `edit/excerpts/drive/<id>/<s>-<e>.<ext>`, `edit/proxies/drive/<id>[/<s>-<e>].mp4`, `edit/proxies/sha256/<hex>.mp4`; this machine's copy of a key is `<cache>/cloud/<key without edit/>`. Script import (`script::footage_to_cloud`): the Drive download (curl stdout) streams into `upload_stream`, progress into the job's bytes; excerpts are cut by FFmpeg reading the original through a presigned URL (seek before input: only those bytes are fetched) into `<cache>/cloud/tmp`, uploaded with their proxy, and removed. `import_paths` uploads footage (hashed, deduped) with a proxy and imports the proxy; sounds and pictures upload as they are and keep their own file (`proxy` = the original's key); the user's files are never touched, and a browser upload's copy in `uploads_dir` is deleted once its footage is up. The proxy (`media::make_cloud_proxy`: ≤1080p H.264 through VideoToolbox, 4 Mbit/s at 1080p down to 0.8 for small pictures, half-second keyframes, no B-frames, BT.709, AAC 160k stereo) is also the preview: `preview.mp4` is a hard link to it, `preview.m4a` its sound copied out. Everything a cloud project uses ends up in the cloud through the backfill (`backfill_soon` / `backfill`): media with no `cloud` whose file is here (made by Edit: smoothed shots, map renders once their footage swaps in, never the `-first.jpg` stand-in; or added while cloud was off, or a failed upload) go up through `upload_made` (dedupe by sha256 like `import_local`; sounds, pictures and video up to 256 MB as their own file, bigger video with a proxy that becomes `path`), one at a time across projects, each saved by its own `store.update` (origin `cloud`) only while the media still has that path and no `cloud`; a failed file waits 10 minutes unless asked. It runs after every push (so only on the machine holding the lock), on open, and where Edit swaps generated media in (`broll::swap_in_smooth` / `swap_media`); `POST /api/projects/{id}/cloud/backfill` or `edit cloud backfill <id> [--port N]` (through the running Edit) runs it now and answers `uploaded` / `failed` / `skipped` / `missing`. A new kind of generated media needs nothing more as long as it's saved through the store (the next push backfills it); call `backfill_soon` to start sooner. Analysis that costs money to redo goes beside the source as `edit/analysis/<drive/<id>[/<s>-<e>] | sha256/<hex>>/` (`transcript.json`, `faces-v1.json`, `seats-v2.json`, `watch/*.json`; `cloud-shared.json` in the media's cache dir records what went or came) and `ensure_local` fetches what this machine lacks (each source looked up at most every 10 minutes). Not shared: loudness, peaks, thumbnails and previews (cheap, made again), and project-level `cache/watch-projects/` receipts. `ensure_local` (called when a cloud project is opened) fetches missing proxies (three at a time, one download per file) and repoints `path` in one `store.update` (origin `cloud`; on a project another machine holds, saved here only via `put_from_cloud`); media neither here nor in the cloud, or still uploading elsewhere, are named in its error and in the cloud status's `missing` (the top bar says "Files missing"), and `for_export` refuses an edit using one, naming it. Exports (`for_export`) never download originals: AVAssetReader refuses non-local URLs (error -11838), so FFmpeg reads each one from R2 through a presigned URL (only the byte ranges it needs, `-hwaccel videotoolbox`, reconnecting on drops: `tools::url_args`) and hands frames to the native renderer and encoder; waveform levels are shared from the proxy's cache. FFmpeg reads URLs with `tools::protocols` / `tools::tls_args` (the static FFmpeg's OpenSSL can't find macOS's certificates: `-ca_file /etc/ssl/cert.pem`). Presigned URLs are credentials: errors go through `cloud_media::scrub`. Live tests (relay + R2 + Convex; the Drive ones also need the Google sign-in): `cargo test -p edit cloud_media::tests::live -- --ignored --test-threads 1`; they remove what they make.
- `crates/edit/src/voice.rs` — voice-overs (`~/.edit/voice/<id>/`): a script import's last step speaks its cut-ins with the house ElevenLabs voice through the relay (`/v1/speech`, `/v1/voices`) and `voiceover::generate` transcribes the takes and splits them across the cut-ins. There's no voice-over screen; a run that stopped part-way picks up the lines already spoken. The relay uses `ELEVENLABS_SPEECH_KEY` (else `ELEVENLABS_API_KEY`) and caps characters per IP and per day.
  - For script-based edits, generate voice-overs during import using the existing house voice and generation tools, then place them across the cut-ins by matching the spoken words to each cut-in's script (`voiceover::place` / `place_voiceovers`). Reuse completed takes. Do not ask for recorded narration unless the user specifically wants to supply it; voice generation is part of starting the edit.
- `apps/web/` — React UI. Per-frame work (playhead, timeline canvas, preview) runs outside React; see `src/lib/playback.ts`.

Projects are `~/.edit/projects/<id>.json`, written atomically (media files they use may be on the media drive, above). Before a save replaces one, the previous version is copied to `projects/history/<id>/<ms>.json` (at most every 10 minutes, the last 30 kept); deleting moves it (and its chat) to `projects/deleted/`. A project file that won't load is listed with its `problem` and never written over.

FFmpeg ships with Edit: releases put `edit-ffmpeg` / `edit-ffprobe` beside `edit` (and `just bundle` into Edit.app's Resources), fetched by `scripts/ffmpeg.sh` (Martin Riedl's signed static macOS builds, pinned by version and SHA-256); `crates/edit/src/tools.rs` finds them, else uses FFmpeg on PATH (dev). Always run FFmpeg through `tools::ffmpeg()` / `tools::ffprobe()`. Users still install Codex (and sign in) and have Chrome; the home screen's setup card (`/api/setup`) says what's missing.

Diagnostics (`crates/edit/src/diag.rs`, `apps/web/src/lib/diagnostics.ts`): the server logs what failed and times every request, agent tool call and turn, media job, script import step, render and export (`diag::record` / `time_on` / `time_async`); lines go to `~/.edit/logs/edit.log` and `GET /api/diagnostics` (version, recent log, per-operation timings). The UI notes its own errors, failed requests, request round-trips and preview waits, and "Report a problem" (⋯ menu, error toasts, the crash screen, a preview stuck on "Loading frame…") joins both into one text to copy. When something new can fail or take a while, time it and log the failure with what it was working on.

`apps/web/src/lib/project-sharing.ts` reconciles incoming server JSON by collection ID and shares unchanged branches with prior undo entries; never mutate the old snapshots. Completed watch receipts in `cache/watch-projects/` describe the corrected transcript state, so changed line grouping does not force a second paid watch. Unchanged cached watches work without an API key. `scripts/benchmark.py` and `scripts/benchmark-history.ts` measure the media, editing and retained-history paths against isolated fixtures.

When the model changes, update `edit-core`, `apps/web/src/lib/types.ts`, the param tables in `apps/web/src/lib/edit.ts`, and the model description in `crates/edit/src/mcp.rs` together.

## Building the dev server

The long-running server (`/tmp/run/edit`, started by `/tmp/run/serve.sh` on :7700) is built with `just serve-build` (UI + Rust) or `just serve-build-rust` (Rust only, when `apps/web/dist` is current). It uses `[profile.serve]` (release opt-level 3 everywhere, but no LTO, 256 codegen units, incremental, unstripped), builds without the `app` feature (no Tauri: 230 crates instead of 312; `edit app` in that binary says to use a browser), puts target and build dirs on the internal SSD at `~/edit-build/{target,build}` (`EDIT_BUILD_DIR` overrides; ~0.8 GB for the server, ~2.2 GB with `cargo clippy` / `cargo test --profile serve` there too), and swaps the binary into `/tmp/run/edit` by rename (`EDIT_SERVE_BIN` overrides), so the running server is safe; restart it yourself when nothing is exporting. On the 8 GB M1: a one-line change in `crates/edit` rebuilds in ~8 s (the release profile recompiles the whole `edit` crate and re-runs thin LTO over everything on every change), a change reaching edit-core/edit-render ~45 s, a clean build 2.5 min (the release one ~10 min; the slowest units are the `edit` crate, naga, tokio and wgpu-core); exports and agent renders run at release speed (a 3-minute export: 169 vs 167 frames/s). To check a change the same way, `cargo clippy --profile serve` / `cargo test --profile serve` with the same `CARGO_TARGET_DIR` / `CARGO_BUILD_BUILD_DIR` reuse its dependencies. Don't put Rust build dirs on the LaCie (a spinning disk: every incremental build reads thousands of small files) or share one build dir between checkouts building at once. While an export runs, build with `CARGO_BUILD_JOBS=2` so it isn't starved. The linker is already Xcode's ld-prime (`ld -v` says ld-1230); no faster linker is worth adding. `just release`, `just publish` and CI keep `[profile.release]` (thin LTO, stripped) with Tauri.

`just check` (fmt, clippy `-D warnings`, tests, typecheck). The render test in `crates/edit-render/tests` needs a GPU; it writes PNGs to `target/render-tests/` for eyeballing.

## Releases and self-update

Versions go up a patch at a time (v0.0.1, v0.0.2, …), never minor or major. With everything committed on `main`, `just publish` runs the checks, bumps the patch in `Cargo.toml` / `Cargo.lock` / `web/package.json` (committed as "Release vX.Y.Z"), and pushes it with its `vX.Y.Z` tag. `.github/workflows/release.yml` then builds the UI once, builds `edit-<target>.tar.gz` (+ `.sha256`) for `aarch64-apple-darwin` and `x86_64-apple-darwin` (cross-compiled on the Apple Silicon runner), and publishes the draft release when both are up. Running the workflow by hand makes a test build (workflow artifacts, no release). Adding a target means a matrix entry plus `install.sh` and `asset_target()` in `update.rs`; removing one breaks updates for that platform.

The repo is public: installs read GitHub Releases directly, no token. `install.sh` (`curl -fsSL https://raw.githubusercontent.com/spheceo/edit/main/install.sh | sh`) fetches the latest archive; `crates/edit/src/update.rs` checks `releases/latest` (GitHub's own SHA-256 digest, or the `.sha256` beside the archive), and the editor's "Update to vX" button (`apps/web/src/lib/update.ts`) downloads, verifies, swaps the binary and execs it in place; the page reloads when the new version answers. Only builds made with `EDIT_RELEASE=1` (the release workflow) update themselves, so dev builds never replace `target/`.
