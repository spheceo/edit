# The code

Everything that builds lives here; the repo's top has the agent's text (`agent/`, see `../AGENTS.md`), the docs and the installer. Run `just` here or at the top.

## Development

Requirements: Rust, Bun, FFmpeg on `PATH`, `wasm-bindgen-cli` matching `crates/edit-wasm` (`cargo install wasm-bindgen-cli --version 0.2.129`), and macOS 26+ for WebGPU in the window. On Linux also `cargo-watch`, `rustup target add wasm32-unknown-unknown`, Google Chrome's .deb (the window, maps; WebGPU with no flags) and, for NVENC/CUDA, NVIDIA's driver 610+ (the FFmpeg a release ships asks for it). Linux's differences from a Mac: the window is Chrome's app window (`linux_desktop.ts`), the sign-in is `<home>/sign-in.json`, exports and previews encode on NVENC (`tools.videoHardware`, `export::nvenc_args`; chunks through `pipe_writer.rs`), faces are YuNet (`face_model.rs`) and words on screen PaddleOCR (`text_model.rs`), both by tract on the CPU.

```sh
just dev      # server on :7700 + Vite hot reload on :5173
just dev-server  # the server alone, as `just dev` runs it (scripts/dev-server.ts: a fresh server on each change, started again if it exits or hangs)
just native   # after a Rust change under `just dev`: builds the addon and swaps it in by rename (the server restarts onto it)
just app      # build everything, open the desktop app
just check    # fmt, clippy, tests, typecheck, lint
just nightly  # tag and publish a nightly (never just publish unless told)
```

Data lives in `~/.edit`; exports go to the folder saved in Settings (`<home>/export-folder.json`), and to `~/Movies/Edit/` until one is saved (`~/Videos/Edit/` when Movies isn't a folder). From another device, `tailscale serve --bg http://127.0.0.1:7700` (WebGPU needs HTTPS).

Environment flags (`EDIT_*`; add one only when a constant won't do, and list it here):

- `EDIT_HOME` — the data folder (`just dev`: `~/.edit-dev`; the trial server: `~/.edit-trials`).
- `EDIT_RELAY_URL`, `EDIT_RELAY_TOKEN` — another relay and its bearer (`just dev` and the trial server: `edit-relay-dev`; tests and a local relay).
- `EDIT_ACCOUNTS_URL`, `EDIT_GOOGLE_API_URL` — another accounts site, and every Google host sent to a test server (`endpoints.ts`); acceptance points the first nowhere.
- `EDIT_TEST_LOCAL_WEB`, `EDIT_TEST_MODEL_URL` — the test mocks' local web and Claude stand-in (`test/mocks`).
- `EDIT_KEYCHAIN_FILE` — a file in place of the Keychain item (tests, packaging's smoke start, acceptance).
- `EDIT_NO_BROWSER`, `EDIT_CLAUDE_MAINTENANCE=0` — packaging's smoke start and acceptance: no sign-in browser, no Claude upkeep.
- `EDIT_ADOPT_SHELL_ENV=1` — set by the window helper when Finder starts `edit serve`: take the login shell's PATH.
- `EDIT_HOSTS` — more Host names the server answers to, comma-separated.
- `EDIT_CLOUD_HOLDER` — the name teammates see for this machine on a cloud lock (tests; the setting otherwise).
- `EDIT_TRIALS=1` — the trial server: kept out of the team's work.
- `EDIT_LOCAL_EXPORTS` — exports at once on this Mac, in place of the chip's count (tests).
- `EDIT_FFMPEG`, `EDIT_FFPROBE`, `EDIT_QJS`, `EDIT_YTDLP` — the tools' paths (tests; else bundled or on PATH).
- `EDIT_YOUTUBE_SIGNIN=0` — no Chrome sign-in for yt-dlp (every test run, `test/setup.ts`).
- `EDIT_LIBRARY_FOLDER`, `EDIT_RENDER_FOLDER`, `EDIT_SUBTITLES_FOLDER` — the Drive folders, for tests.
- `EDIT_NIGHTLY`, `EDIT_RELEASE`, `EDIT_VERSION` — build defines from the release workflow (`version.ts`); `EDIT_VERSION` also pins `install.sh`.
- `EDIT_SERVER`, `EDIT_HTTPS=0` — Vite: the server it proxies to, and plain HTTP in place of the Tailscale certificate.
- `EDIT_TRIAL_PORT`, `EDIT_TRIAL_HOME` — the trial server's port and data folder (`scripts/trial-server.sh`).
- `EDIT_BUILD_DIR`, `EDIT_SERVE_BIN` — `just serve-build`'s build folder and where it swaps the binary in.
- `EDIT_CLOUD_LIVE`, `EDIT_DRIVE_LIVE`, `EDIT_AUDIT_PROJECT`, `EDIT_AUDIT_CACHE`, `EDIT_WATCH_SOURCE`, `EDIT_WATCH_TRANSCRIPT`, `EDIT_WATCH_WINDOW`, `EDIT_WATCH_BENCH` — opt-in tests against real services or files.
- `EDIT_NO_GPU=1` — the native tests skip their GPU cases.
- `EDIT_PREVIEW_CHECK`, `EDIT_PREVIEW_TRACE`, `EDIT_PREVIEW_SHOT` — the window's native preview check, its trace and its screenshot (`docs/preview.md`; check.yml's `native` job runs on them).
- `EDIT_FFMPEG_VIDEO=1`, `EDIT_FFMPEG_AUDIO=1` — FFmpeg's decoders and mixer in place of the native ones, for diagnosis.
- `EDIT_REQUIRE_GPU=1` — a render refuses a CPU adapter.
- `EDIT_SMOOTH_QUALITY` — VideoToolbox's frame-rate conversion at quality, not speed (`mac_media.m`).
- `EDIT_RENDER_SOURCE`, `EDIT_SOUND_SOURCE` — set by build.rs: hashes of the drawing and mixing code that key reused chunks and sound.
- `EDIT_TRACK_REAL`, `EDIT_LOUDNESS_FILE`, `EDIT_DESKTOP_SAMPLES`, `EDIT_WRITE_PEOPLE_CASES=1` — Rust tests: real footage, samples written out, the people cases rewritten.
- `EDIT_EXE` — read by the engine for the installed binary's path; nothing sets it since the window became its own helper.

## Layout

Paths are relative to `app/`.

- `crates/edit-core` — project model and frame evaluation. Pure Rust, no I/O; compiles natively and to WASM. Timeline times are integer frames; `source_in` is seconds. `Project::validate` is the contract every writer (UI, MCP) must satisfy.
- `crates/edit-render` — the wgpu compositor. The browser preview and the export both call `Renderer::render`; never add an effect to only one side. Shaders live in `src/shaders/`.
- `crates/edit-wasm` — wasm-bindgen wrapper; `just wasm` writes `apps/web/src/engine/pkg` (generated, gitignored).
- `crates/edit-engine` — the native engine, the Rust behind the server: frame renders and exports (`render.rs`, `export.rs`, `mix.rs`), probing and preview making (`media.rs`), loudness, tracking (`track.rs`, `motion.rs`), face detection (`faces.rs`: `detect`/`cached`), censor checks, camera angles (`seats.rs`: `scenes`), the desktop profile's drawing (`desktop.rs`) and `mac_media`. It knows nothing of the server (no store, events or HTTP): the host (the addon) sets FFmpeg and the cache (`util.rs`: `use_tools`, `use_cache_dir`) and takes its log lines (`log.rs`, a sink, which the server's `diag.ts` writes).
- `crates/edit-window` — the desktop window as its own small Tauri program (app.rs's `run`): `edit app` extracts it from the binary to `<home>/bin/Edit` (the Dock's name) and runs `Edit --url http://127.0.0.1:<port>/`; it quits when its stdin closes. Without `--url` it's Edit.app (`just bundle`) and starts `Resources/edit serve` itself (Ctrl-C to it when the window closes).
- `crates/edit-native` — the napi-rs addon over edit-engine and edit-core for the Bun server. Bindings only: every call converts, calls the engine, and turns `Err(String)` into an `Error` with the same message; panics are contained (`edit_engine::util::catch`); async calls run in tokio's blocking pool, progress and log lines come through weak `ThreadsafeFunction`s (callbacks must not throw). `just native` builds `edit-native.node` and writes `index.d.ts` (napi-rs, with `dts-header.d.ts` importing the ts-rs types; committed, and `just check` fails if it drifts); `just native-test` runs `test/*.test.ts` under Bun (GPU ones skip without a GPU or with `EDIT_NO_GPU=1`); `just native-compiled` checks the addon embedded in `bun build --compile` (re-sign with `codesign -s - -f` after compiling: Bun leaves the signature invalid). A napi `cdylib` can't link into a normal binary, which is why the engine is its own rlib.
- `packages/edit-types` (`@edit/types`, what the server and the UI type the project with) — the project model and the engine's options as TypeScript, generated by ts-rs (`ts` feature on edit-core and edit-engine) into `src/generated` by `just types` (i64 as `number`; fields serde leaves out are `?:`); committed, and `just check` fails if they don't match the Rust.
- `apps/server` — the server, on Bun: `edit` / `edit app` opens the editor in a window (`window.ts` extracts and runs `crates/edit-window`; links out open in the browser; WKWebView has no `window.confirm`/`alert`, so don't use them in the UI, and its WebGPU validates more strictly than Chrome's: a viewport outside the target drops the whole frame), and `edit serve` is the same thing headless: REST + websocket events, FFmpeg media jobs, native frame renders through the addon, export, MCP at `/mcp` (`?project=` scopes a connection to one project), and `agent.ts`, the agent panel's bridge to one of two providers: Claude Code, the only one the UI offers (Oct 24: Codex is hidden; the panel sends no model or thinking level: a turn without one runs on `Agent.turnModel` (Opus to build, the menu's pick to revise) at the menu's level; a caller naming a model, the teaching loop's `round.py`, gets it for that turn and Edit's retries; `POST /api/agent/provider` can still switch to Codex until Edit restarts) (`claude.ts`: the user's own installed `claude` driven through Anthropic's Agent SDK, signed in by the user with `claude auth login` on their own plan or API key; Edit never touches the sign-in, which is what Anthropic's terms allow; one `query` per turn resuming the project's session, no built-in tools, none of the user's settings, hooks or MCP servers, Edit's MCP pre-approved, compacting near 150k tokens), or Codex through `codex app-server`. A chat started on one provider starts a new conversation on the other. Edit ends a turn itself when its agent can't: a stop not answered in 15 s, 25 minutes without a word (tools give up at 15), or Edit quitting (SIGINT or SIGTERM: Claude Code closed, Codex stopped, the chat saying so; running turns are listed in `<home>/jobs.json` (kind `turn`) as they start, noted every minute while they run and crossed off as they end, so a quit or a crash leaves the ones it cut, and when Edit is back within 10 minutes, a restart, the one resumer carries each on as a new turn of the same conversation, so restarting the dev server for a new build never costs an agent its task); Codex going away ends only Codex's turns, and a Claude session Claude Code no longer has is started again as a new conversation in the same turn. `ask` takes a model: a Claude one (`claude-…`) goes through Claude Code, text only (`claude.ask`: no tools, no session kept, structured output for the schema; speakers.ts names voices with `claude-opus-5-5`), any other through Codex (captions.ts's watcher: `gpt-6-luna` with sound and pictures). `main.ts` → `cli.ts` (the `edit` command), `serve.ts` (binds, Tailscale, the App, every package's tools and routes, cloud start/shutdown), `routes.ts` (the generic handlers and `buildRouter`, which puts every package's routes in), `http/` (router, files with ranges and 304s, compression). The addon's contract is `src/native/index.ts` (`stub.ts` stands in for tests without `crates/edit-native` built; it is not the engine). Packages reach each other only through `src/seams.ts`. Live projects are frozen: `store.checkout` or `store.update` to change one. MCP: `src/mcp/tools.json` declares every tool (names, descriptions, schemas) and `instructions.ts` is the core house style; a package's tools register when its module is imported (`registerEditingTools()` in `edit_tools.ts`, `registerMediaTools()` in `media_tools.ts`, the rest as the seams load) and its routes go on the router through its `routes(router)`. Read tool arguments into model types with `clips.ts` / `serde.ts` (serde's defaults, f32 rounding and error words) and write numbers and strings into agent text with `rust.ts` (`round` half away from zero, `fixed` for `{:.N}` with ties to even, `f32Saved` for an f32 as saved, `{:?}` quotes; project files and caches are still written by edit-core, so these keep its formatting). Google calls go through curl with the sign-in on stdin, or fetch with redirects followed by hand so a Google call never leaves https; files broll makes are named by `hash.ts` `fingerprint` (pinned by a test, so caches stay valid). A release's entry is `src/embedded.gen.ts`, written by `scripts/embed.ts` (the UI, the addon and the window helper inside the binary; gitignored); `bun build … --compile` then `codesign -s - -f`. `test/mocks/` stands in for every outside service: `server.ts` (relay, a stand-in for Claude's answers through `model.ts` and `ai_claude.standIn`, Google; `mock.doc` / `mock.driveFile`) and `cloud.ts` (the relay's `/v1/cloud/*`, R2 behind presigned URLs and Convex in memory). A media whose path becomes its cloud proxy takes its analysis along (`carryAnalysis`): the watcher's answers are named by the media key, so the older keys are listed in `watch/keys.json` (`watch.ts` `otherKeys`), which goes to the cloud with the rest. Checks: `bun run --cwd apps/server typecheck` and `test`.
- `apps/server/src/writer/`, `apps/web/src/writer/`, `packages/edit-types/src/writer.ts` — **Script mode**: Writer, merged in Oct 29 2026 (`docs/writer.md` is how it works). Home lists scripts in its Scripts section, by stage, and `/scripts/<id>` opens one; a script's Start the edit makes its Edit project on this Mac (`writer_handoff.ts`), and its recordings and words go to Edit's originals and analysis after import (`writer/handoff.ts`), so Edit mode neither downloads nor hears them again. Its data stays Writer's (Convex `writer:*`, R2 `writer/scripts/<id>/`, through the relay's `/v1/cloud/writer/*`, `apps/relay/src/writer_cloud.ts`), so the old Writer app works on the same scripts; a script takes the same cloud lock as an edit (`writer/locks.ts` on sync_core.ts: Convex's lease under `writer-<id>`, held while the script page has it open here (`POST /api/writer/scripts/{id}/open`, a 30 s heartbeat), an import or Claude works on it here, or briefly after a push), a save to one another computer holds is refused (423) and the page shows who with Take over, a push goes only with the lock (or where the cloud keeps none for scripts, which then sync as before), and a commit is written down in the ledger before it goes so one whose answer was lost is never kept as a copy (`writer/cloud.ts` `ownCommit`); the first start copies the Mac's Writer folder in (`writer/index.ts`). Permissions are Writer's ids (`scripts.*`, `review.*`) on Edit's accounts (`writer/can.ts`). Everything else it needs is Edit's: Claude (`writer/claude.ts` over `claude.ts`), hearing, watching, YouTube, research, Drive and Docs (the team Google sign-in), logs (`[writer]`), remote support. Repack's script guides and the house rules are `agent/writer/`, word for word.
- `scripts/cloud-sweep.ts` — footage in R2 no cloud project, script or local project uses (a deleted project's: Convex deletes only its body) and temporary pieces left behind. Report only by default; `--delete` deletes only what's been unused at every run for 14 days (noted in `edit/sweep/unreferenced.json`) and temporary pieces over 2 days old. Run by hand under `infisical run … --path=/edit-relay`; it touches nothing outside `edit/` (the bucket is Repack's too).
- `assets/sfx/` — sound effects compiled into the `edit` binary (`apps/server/src/sfx.ts`), so every install has them; written on first use to `~/.edit/sfx/<name>-<hash>.wav` (a new version is a new file, so old projects keep theirs). Each ships with a "hit" marker (media markers) that `add_sound_effect` lines up on the cut. `shutter.wav` is the first shutter from https://youtu.be/R24UqkKj90w, trimmed to 0.17 s.
- `apps/server/src/library.ts` — the team's sound library: the "Music & SFX Library" folder in Google Drive is the source of truth (a folder per category under Music / Sound effects, plus an index .txt of per-file notes and a usage-guide Doc). Edit lists it through the Drive API and downloads a sound on first use to `~/.edit/library/<music|sfx>/<checksum>/`; nothing is bundled. Its Google sign-in comes from the relay (`/v1/cloud/google/token`, a short-lived access token for Edits with the cloud token), unless `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET` and `GOOGLE_DOCS_REFRESH_TOKEN` are set on the machine (`just dev` borrows Repack's from Infisical); Docs imports, Drive links and Drive uploads share it. The agent's `list_library` / `add_from_library` use it (the UI's Library tab went Oct 24). A sound it places is tagged `media.library` (`music` / `sfx`): a cloud copy's path (the cache's `originals/sha256/…`) no longer says `library/`, and untagged music had been sorted as speech and transcribed; `tagSounds` tags older projects on open by file name against the listing, and the cloud repoint keeps the tag a library path implies. One download per file at a time (a second ask waits for it); curl gives up on a stalled one, so it's retried rather than held forever.
- `crates/edit-engine/src/loudness.rs` — every measurement of sound (`library.levels` / `loudness`: `measure_audio`, `set_loudness`, `add_from_library`'s `loudness` and `under_speech`, voice-over levels) is arithmetic over the file's analysis: one FFmpeg decode makes 10 ms blocks of K-weighted energy and sample peak, kept as `<cache>/<media key>/loudness-v1.bin` (the media key covers size and mtime, so a changed file is analysed again) and in memory. It matches FFmpeg's `ebur128` (padded with 0.5 s of silence) within 0.5 LU (`matches_ffmpeg_ebur128`); a new method or layout is a new file version. Imports analyse in the background; `prepare` analyses several files three at a time. `library.footageLoudness` is the edit's speech (the footage's sound, else its voice-overs), what `under_speech` counts down from.
- `apps/server/src/cutin.ts` — `cover_cut_in`: the agent picks a cut-in's B-roll shots and this lays them out the house way in one call (butted shots, push-ins, B-roll look, vertical drop, card gone, voice-over to A1). Slowed clips use native frame sampling; optical flow is opt-in (`smooth: true`; the user wants it almost always, so making it fast and automatic is speed-plan 2.2), one render at a time in a lane of its own (never the media processor's slot, so imports don't wait behind it), stopped while an export runs, and limited to 120 seconds of running per shot. Exports take the current timeline snapshot immediately unless `wait_for_smoothing` is explicitly requested.
- `apps/server/src/broll.ts` — `map_view` renders the map page in headless Chrome (one at a time on an 8 GB Mac, two with 16 GB or more: `MAP_RENDERS_AT_ONCE`). A moving shot (at most 12 s: every frame waits on tiles, 0.15–1.9 s each) answers once its first frame and building track are in and renders the rest in the background: the media is that first frame (`map-<key>-first.jpg`) until the footage swaps in under the same media id. A render is stopped only when it stalls (nothing new from the page for `mapStallMs`), never for being slow: each restart is a minute of loading and a paid session from the relay's daily allowance. Frames land whole on disk, and what was asked is kept beside them (`map-<key>.job.json`), so a render cut short carries on from them: when `map_view` is called again with the same arguments, after a restart (jobs.json kind `map`: crossed off only once rendered; a render that ran out of time stays `waiting` for its own retry a minute later, one that failed for good stays `failed` with why), or when an export finds the stand-in on the timeline (`waitForMaps` starts each stuck one again once, then waits). Exports wait for a map still rendering (the agent's up to 10 minutes, the UI's a few seconds) and refuse a stand-in whose render failed again or that has no job file, saying so; they never export the still by mistake. Each map keeps its job file for good and its measured JSON says the look it was drawn with (`look`): when a fix makes earlier maps wrong, raise `MAP_LOOK` and an export draws each older map on its timeline again (`redoOutdatedMaps`: same media id, place labels moved by how far the building moved, `repinLabels`); maps from before job files existed (Oct 21) can't be. The page grades on the GPU (a post-process stage) and draws close views at 1x, wide ones (range ≥ 500 m) at 1.5x against shimmer; most of a frame is the GPU drawing it (the read back), and each map's JSON has `spent`, its time by stage. `track_region` (`crates/edit-engine/src/track.rs`) template-matches small greyscale frames (the box ~40 px wide; the light preview when frames are looked at ≤640 wide, else the original, so a small face in a zoomed-in shot isn't blurred by the preview; AVFoundation on macOS, FFmpeg otherwise) at the footage's rate for stretches up to 40 s, 15 fps beyond; each frame the box is first carried by the camera's move (`motion.rs`: shift, turn and zoom fitted to a grid of patches, cuts detected), searched coarse to fine to a fraction of a pixel with a centre-weighted template (less weight on the wall behind a face), held to the box as given against drift, lost when matches are weak (it rides with the camera; reported), looked for anywhere after a cut (confirmed by the next frame). `boxes` adds sightings: passes run from each to the next, their drift is spread back so they meet each sighting, and they're blended; the path is smoothed by a centred local line fit (no lag), never across a cut. Positions go through the footage's keyframed framing (a push-in), which the static transform missed. Frames are kept a few minutes for another pass; coordinates stay in source pixels. `real_bench_face` (ignored; `EDIT_TRACK_REAL`) measures it on Mom & Teen's bench shot.
- `apps/server/src/edit_plan.ts` — `apply_edit_plan` applies a whole stage in memory (times in frames; `add` needs start and duration; `transition`, `evidence_board`, `date_title` and `place_label` build house graphics in one line (`graphics.ts` has the last two: the date cut-in's date is white with only a drop shadow over a darkening adjustment, never boxed or glowing; the map's place label is the house label pinned to `building_track`; `cover_cut_in` puts every picture shot on the Windows screen, so a found photo is never plain B-roll): an evidence board is framed photos (video clips' `frame`: border and drop shadow) on paper, the camera in one continuous glide past them (each photo centred at its `at`, the frame of the word naming it; a smooth S whose speed eases to ~70% of its average at each photo and picks up between, never stopping) and red notes in Reenie Beanie writing on; each photo's `at` is marked ("board photo") and gets a quiet bundled shutter whose click lands on it, unless `shutters: false` or another shutter is within 8 frames; `title_collage` is a courtroom compilation's title card (its title starts "When…"): one framed photo per case, a row above and a row below, the title in big glowing capitals between them over a darkened courtroom (`graphics.ts`); `markers` as the markers tool; moving or deleting one half of a linked pair takes the other along unless `unlinked`), resolves named references, validates the final project and commits once with `base_rev`; an invalid/stale plan saves nothing, except that a plan on a revision the agent was shown still saves when only background work (a cloud upload, a smoothed shot or map swapped in) changed `media` since (`edit_tools.onlyMediaChanged`). Its `audit` is the mechanical review (picture gaps, slivers, bare cut-in cards, exhausted sources, misaligned linked sound, review notes like "[unclear]" left in on-screen text, the same B-roll moment in two places, transitions with no sound, a subtitle past its cut, footage under 8 frames, a picture on screen outside a designed graphic (`bare_still`, `letterboxed`), a boxed or glowing date (`date_style`), words on a track under a blur over them (`text_under_blur`: a redaction above a label blurs it); and, where the MCP side adds what needs the media cache: B-roll that's mostly pixelated or blurred, `censored_broll`, and quote callouts off the words that point to them, `callout_off_speech`, from `edit_review.calloutTiming`), so the agent renders only for judgement. The plan's house pictures and sounds (the board shutter, the desktop's wallpaper and windows) are added to the plan's own copy of the project first (`edit_tools.planAssets`, `import.houseMedia`), so it still saves once or not at all. A plan that adds or relabels text ends with `people.oneColourPerPerson`. Begin with `get_edit_context`: one line per clip, cut-in words as `word@seconds`, narrowed by `section` (intro / story / outro) or start/end, capped near 36k characters (Codex truncates tool output at ~10k tokens). `find_in_footage` (`footage_search.ts`) searches every footage transcript for many phrases in one call (B-roll candidates). `batch` runs independent lookups three at a time. Its `transition` op builds drop, flash, dip and open, and two styles' own: `light_leak` (courtroom: 16 frames of warm light sweeping across and burning to white on the cut) and `burn` (interrogation's "Bridge flash": 12 frames burning out warm), both on the adjustment's `grade.leak` / `leak_x` (the renderer's light leak, `adjust.wgsl`: warm light added from one side, orange where faint, white where strong; keyframable); the audit never calls them repetitive but wants each heard.
- `apps/server/src/intro_graphics.ts` — the interrogation intro's house graphics, one plan op each, learnt from Red Thread Interrogations and Red File (docs/feedback/2026-10-19-interrogation-intro.md): `intro_captions` (the teasers' subtitles restyled: boxed lines coming up word by word, white on black, the lines that matter on red, naming nobody so the role colours don't apply; `edit_tools.hearWords` fills in the frames words are heard at), `countdown` (one text clip a second), `fast_forward` (a keyed glitch and "FF >>"), `disclaimer` (the house's own words), `text_slam` and `timeline_bar` (Red File's: the line is the second year's leader); plus edit_plan's `red_flash` transition and date_title's `position: "bottom"` with `place`.
- `apps/server/src/reset.ts` — `reset_edit` ("reset the video", Oct 24): the edit back to the script import's first layout (every clip, timeline marker, in/out, segment and the cast gone; the script laid out again by `script.layOut`; the voice-over takes put back by `voiceover.generate`, which reuses the takes spoken), so a project can be edited again from the start with what the agent has learnt since. The tool never acts alone: it asks in the chat (a `reset` event, `GET/POST /api/projects/{id}/reset`, the agent panel's Accept / Reject card) and waits up to 10 minutes; the edit before is written to `projects/history/<id>/` first. Blocked in review-fix turns.
- `apps/server/src/playback_render.ts` — smooth playback (`docs/preview.md`): the open edit rendered in the background on this Mac through the export's chunks (its own folder, `<id>.playback`), one at a time, in a place in the export line ahead of the queued exports (`ExportRegistry.takeTurn`: it waits only for one rendering, and runs beside them on a Mac with room), the chunk at the viewer's playhead first (`Plan.focus`: the minute from it, then the sound's mix, then the rest, never the mix beside the decoders), and after an agent's turn by itself; a render of the same picture already in R2 (`cloudKey`) is played instead. `playback_stream.ts` serves it a chunk at a time as each lands (`/playback/stream?rev=` says which chunks are ready, a plan older than the render is never served as it; `/playback/segment/<key>` remuxes one to fragmented MP4; `/playback/sound` the mix, then the joined file's), and the page's `smoothStream.ts` appends them to a MediaSource around the playhead (20 s behind, 2 min ahead), its sound in an `<audio>` kept in step; where no chunk is in, the viewer draws live. Measured Nov 2 on the 16-Year-Old (26.7 min): a seek shows it in 0.5–1.6 s, it plays at 30 fps, and a render under way shows its first chunk 17 s in (it waited 142 s for the whole mix before). A test that waits on timing is made to watch the state instead (a signal, a file, the process's state), never given a longer sleep.

Tests and steps that skip on GitHub's virtual Macs, and why: `mac_media::smoothed_frames_keep_the_footages_brightness` when VideoToolbox refuses frame rate conversion (-19730), and the renderer's GPU tests without a GPU (Linux's legs use Vulkan's software device instead).

Preview/export parity can be verified in a browser: `window.__edit.preview.engine.render(frame)` then read the canvas, and compare with `GET /api/projects/{id}/frame/{frame}.png` — graphics-only frames are byte-identical.

## Releases and self-update

Claude Code maintenance (`apps/server/src/claude_support.ts`) runs once on the first start of each installed nightly, recorded before it begins in `<home>/agent/claude-support.json`, never on every launch. It updates the user's own CLI, diagnoses installation and credential sources, verifies a real `claude -p` request and the Agent SDK connection, and lets the CLI own browser sign-in. Auth failures retain the user's message in `agent/claude-pending.json` and resume it once after verification; Stop, New Chat, a newer message or a provider change cancels the retry, and the cloud lock is checked again. Report only scrubbed diagnostics; never store tokens or authorization URLs. Packaging's smoke start sets `EDIT_CLAUDE_MAINTENANCE=0`. See `docs/claude-setup.md` at the repo root.

Remote support (`apps/server/src/remote_support.ts`, `remote_actions.ts`; Convex's `editSupport`, on mamagi): every signed-in Edit registers its device at every start, always on (no off switch: Sphe, Nov 1), and an admin sends it commands from their own Mac with `edit remote devices`, then `edit remote update <device>` (install the newest build), `edit remote diagnostics <device>` (a problem report, `GET /api/reports`, that leads with what needs attention: a nearly full disk, nobody signed in, the relay not answering, setup not ready, imports and syncs that stopped, agent turns quiet 15 minutes; then the machine, the work under way, every recurring warning and error of the last two days grouped with its count and latest example, the projects, the scripts, timings and the end of the log; `GET /api/remote-support/report` shows this Mac's own), `edit remote resume <device> <project-or-script>` (a project only on that Mac goes to the cloud, then an unfinished import starts again), `edit remote unstick <device>` (syncs waiting out a failure tried again, stopped imports of projects and scripts started again, agent turns quiet 15 minutes stopped, the cache cleaned on a nearly full disk) or `edit remote restart <device>` (Edit started again in place, refused while an export, an import, Claude on a script or an agent turn would be cut off). `edit remote update-when-idle <device>` asks the update to install itself once nobody has used the window for 20 minutes and nothing's running (kept across restarts; Sphe, Nov 1: "dont restart the app while mathias is using it, wait for idle"), and `edit remote probe <device> <project-or-script>` sends a report of one import's whole error, its source files' streams and a decode of their sound, so a damaged file is seen without fetching it. unstick, restart, update-when-idle and probe-<id> ride on resume (reserved targets in `remote_actions.ts`), so Repack's Convex knows only update, diagnostics and resume. None of them runs the agent. To fix something found in a report: fix it in code, ship a nightly, then `edit remote update <device>`. `edit remote history <device>` says how each went. A device asks only for the kinds it carries out (`pending`'s `kinds`), so builds from before diagnostics and resume still get updates alone. From this checkout with no Edit running, `bun apps/server/scripts/remote.ts devices|latest|ask|diagnostics|probe|history|…` does the same straight against prod (the admin signed in to `~/.edit-dev`; `--dev` for dev, where the dev server is a device): `ask <mac> <question>` (`remote_ask.ts`, an `ask-<base64url>` resume target of at most 120 characters) answers read-only questions (the log by time, level, area and pattern across its five rotations; system; processes; network; work under way; a project; files in the data folder, sign-in files refused; Edit's own GET routes), scrubbed, sent up under `edit/reports/remote/`. The skill `.agents/skills/remote-diagnose` is how to go about it.

**Dev and prod** (Oct 31, Sphe: "everything we do is done in dev and when the nightlys are pushed that uses prod"). Each piece has a dev and a prod copy, and dev never touches what the team's installs use:

| | Dev: `just dev`, the trial server, agents | Prod: installed nightlies and releases |
|---|---|---|
| Relay | `edit-relay-dev` (wrangler `[env.dev]`; `just dev` and `scripts/trial-server.sh` set `EDIT_RELAY_URL` to it) | `edit-relay` (`relay.ts`'s default) |
| Secrets | Infisical Platform `dev` `/edit-relay` | Infisical Platform `prod` `/edit-relay` (`CONVEX_*` reference `/mamagi`) |
| Convex | `determined-heron-867` (mamagi's `development` deployment: the accounts repo's `convex/`, deployed with Infisical dev `/mamagi`'s key; its settings are dev's own) | mamagi, `unique-shrimp-228` |
| R2 | the `edit-dev` bucket, with a key for it alone | the bucket shared with Repack |
| Data folder | `~/.edit-dev` (`just dev` sets `EDIT_HOME`) | `~/.edit` |

Dev starts empty: `just copy-to-dev --list` names prod's projects and `just copy-to-dev <id or name>` copies one in (`scripts/copy_to_dev.py`: its body, its footage's rows, and on R2 everything it names plus the analysis beside it; prod is only read; copying again replaces dev's copy and skips what's already there). A change to mamagi's functions goes to dev as well as prod: `infisical run --env=dev --path=/mamagi -- bunx convex deploy -y` in the accounts repo. Deploy dev by hand whenever (`npx wrangler deploy --env dev` in `apps/relay/`). Never deploy prod by hand: a nightly's tag does it (release.yml's `cloud` job: `wrangler deploy` of the live relay; repo secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`), so prod only ever runs code that shipped. Secrets go by hand from their own environment to their own Worker: `bun scripts/push-secrets.ts --yes` is dev's, `--env prod --yes` the live one's (never Infisical's leftover `MODAL_*`).

Builds are named by their tag everywhere ("edit v0.0.0", "edit nightly-1": `edit --version`, Settings, the update pill, release titles). Versions go up a patch at a time (v0.0.0 was the first, then v0.0.1, …), never minor or major. **Never move to a new version (`just publish`) unless the user says so**, each time: an agent ships nightlies, not versions. In between are **nightlies**: `just nightly` (everything committed on `main`) tags main's head `nightly-<N>` (the next number) and pushes; the workflow builds it like a release with `--define EDIT_NIGHTLY=<N>` (`apps/server/src/version.ts`: `BUILD` is then "nightly-N", what the editor and `edit --version` show) and publishes it as a GitHub pre-release, so `releases/latest` (Stable, `install.sh`) never sees it. With everything committed on `main`, `just publish` runs the checks, releases the current version if it was never tagged, otherwise bumps the patch in `Cargo.toml` / `Cargo.lock` / `apps/web/package.json` / `apps/server/package.json` (committed as "Release vX.Y.Z"), and pushes it with its `vX.Y.Z` tag. `.github/workflows/release.yml` then builds the UI once, builds `edit-<target>.tar.gz` (+ `.sha256`) for `aarch64-apple-darwin` (Apple Silicon only: the Intel build was dropped Oct 29, the whole team is on Apple Silicon; an Intel install finds no asset and offers no update), and publishes the draft release when it's up. Running the workflow by hand makes a test build (workflow artifacts, no release). Each build also makes **Edit.app** (`scripts/package-app.sh`: the Tauri window with `edit`, `edit-ffmpeg` and `edit-ffprobe` in its Resources), its update zip `Edit-<target>.zip` (+ `.sha256`) and the disk image people install from, `Edit-Apple-Silicon.dmg` (`scripts/make-dmg.sh`: dmgbuild lays out the window, `scripts/dmg/background.swift` draws it; Finder writes names in dark grey over a picture, so each sits on a light tag, and never set dmgbuild's `hide_extensions`: its Finder info breaks the app's strict signature check). With the repo secrets `MACOS_CERTIFICATE` (Developer ID Application .p12, base64) and `MACOS_CERTIFICATE_PASSWORD` everything is signed with the Developer ID under the hardened runtime (`scripts/dmg/edit.entitlements`: Bun's JIT and its unpacked addon); with `NOTARY_KEY` (App Store Connect API .p8, base64), `NOTARY_KEY_ID` and `NOTARY_ISSUER` the disk image is notarised and stapled; without them it's all ad hoc. Once signed, `package-app.sh` starts the app's `edit` (`--version`, then `serve` until `/api/health` answers) and fails the build before the disk image if it doesn't: a Bun-compiled binary can hang at start under the hardened runtime, which no earlier step shows (Writer's did with Bun 1.4.4, Oct 23). CI's Bun is pinned (`bun-version` in release.yml, 1.4.0, the version Edit is built with here); move it only after a signed build of the new one passes that check. An Edit running inside Edit.app updates from the zip and replaces the whole app (`update.installApp`: unpacked beside it, signature checked, same team, two renames; files inside a signed app are never swapped), then execs the new app's server at the same path; the window carries on until Edit is next opened. Adding a target means a matrix entry plus `install.sh` and `assetTarget()` in `apps/server/src/update.ts`; removing one breaks updates for that platform.

**Nothing ships past a red Check, and one nightly a day** (Nov 8 audit, item I; Sphe: sixteen nightlies in a week made the team the test suite). release.yml's first job, `checked`, finds check.yml's run for the tagged commit's push to main and waits for it (Check takes about 15 minutes; nothing is checked again there, the Mac runner being scarce), and stops the release unless both legs, the Mac's acceptance included, passed. A tag on a commit that was never pushed to main has no Check run and fails. **When Check is red, fix it first**: push the fix to main, let Check pass, then `just nightly`; there is no override flag, and none should be added. `just nightly` refuses a commit Check already failed on, and a second nightly within 20 hours of the last: one that can't wait is `just nightly --force "<what it fixes, for whom>"`, the reason kept in the annotated tag's message (`Forced: …`) and shown in the release's notes. The notes are made by `scripts/nightly-notes.ts` (printed by `just nightly` before it tags, written by release.yml's `prepare` as the pre-release's body): two lines for the team (how many changes, by the plan item their messages name, "(Nov 8 audit, item G)", named from `docs/plans/*-audit.md`, and the first clause of the newest of each), then every change by its first clause, grouped the same way. So a commit message's first clause is what the team reads: say in it what changed for them. Running the Release workflow by hand (a test build) isn't gated.

A new build tries again, once, what failed on the one before (`apps/server/src/retry_after_update.ts`; Sphe, Nov 2: "could we make changes so that these failed stuff can restart when a new nightly comes on"): the first start of a build whose tag differs from `<home>/last-build.json` (or with none kept) queues, in jobs.json (each failed job's `retry`, set to the build), each share of a Ready for changes' fixes that failed (`reviews.unshared`) and each export that failed and hasn't been exported since (a failed `export` job; a share's own export is the share's), then while the Mac is idle (`reviews.busyHere`: no export, share, import, agent turn or fix) takes them one at a time, off the queue before it starts. Never on a project another computer holds, a share never on an approved review or one a reviewer asked of this Mac again (that request does it); the project's chunk cache goes first. Each says "Trying again after the update" in the log and the Exports panel; failing again, it waits for the next build.

The repo is public: installs read GitHub Releases directly, no token. `install.sh` (`curl -fsSL https://raw.githubusercontent.com/spheceo/edit/main/install.sh | sh`) fetches the latest release's archive (`EDIT_VERSION=v0.0.N` or `nightly-N` for a pinned install or a rollback, `EDIT_VERSION=nightly` for the newest nightly) and puts every program in it beside `edit`. `apps/server/src/update.ts` checks GitHub on the install's channel (Settings → Updates, kept in `<home>/update.json`): Nightly, the default, offers whichever release or nightly was published last (a nightly ahead by its number, a release by its version), Stable only `releases/latest`, and never a downgrade (a nightly you're on waits for the next release). The editor's "Update to nightly-N" / "Update to vX" button (`apps/web/src/lib/update.ts`) downloads, verifies, swaps in every program in the archive (executables at its top, `edit` last; so a later release can add a window helper or an addon and older installs pick it up) and execs it in place; the page reloads when the new version answers. Only builds compiled with `--define EDIT_RELEASE=true` (the release workflow) update themselves, so dev builds never replace themselves.
