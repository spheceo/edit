# The code

Everything that builds lives here; the repo's top has the agent's text (`agent/`, see `../AGENTS.md`), the docs and the installer. Run `just` here or at the top.

## Layout

Paths are relative to `app/`.

- `crates/edit-core` — project model and frame evaluation. Pure Rust, no I/O; compiles natively and to WASM. Timeline times are integer frames; `source_in` is seconds. `Project::validate` is the contract every writer (UI, MCP) must satisfy.
- `crates/edit-render` — the wgpu compositor. The browser preview and the export both call `Renderer::render`; never add an effect to only one side. Shaders live in `src/shaders/`.
- `crates/edit-wasm` — wasm-bindgen wrapper; `just wasm` writes `apps/web/src/engine/pkg` (generated, gitignored).
- `crates/edit-engine` — the native engine, the Rust behind the server: frame renders and exports (`render.rs`, `export.rs`, `mix.rs`), probing and preview making (`media.rs`), loudness, tracking (`track.rs`, `motion.rs`), face detection (`faces.rs`: `detect`/`cached`), censor checks, camera angles (`seats.rs`: `scenes`), the desktop profile's drawing (`desktop.rs`) and `mac_media`. It knows nothing of the server (no store, events or HTTP): the host (the addon) sets FFmpeg, the cache and the media folders (`util.rs`: `use_tools`, `use_cache_dir`, `use_media_folders`) and takes its log lines (`log.rs`, a sink, which the server's `diag.ts` writes).
- `crates/edit-window` — the desktop window as its own small Tauri program (app.rs's `run`): `edit app` extracts it from the binary to `<home>/bin/Edit` (the Dock's name) and runs `Edit --url http://127.0.0.1:<port>/`; it quits when its stdin closes. Without `--url` it's Edit.app (`just bundle`) and starts `Resources/edit serve` itself (Ctrl-C to it when the window closes).
- `crates/edit-native` — the napi-rs addon over edit-engine and edit-core for the Bun server. Bindings only: every call converts, calls the engine, and turns `Err(String)` into an `Error` with the same message; panics are contained (`edit_engine::util::catch`); async calls run in tokio's blocking pool, progress and log lines come through weak `ThreadsafeFunction`s (callbacks must not throw). `just native` builds `edit-native.node` and writes `index.d.ts` (napi-rs, with `dts-header.d.ts` importing the ts-rs types; committed, and `just check` fails if it drifts); `just native-test` runs `test/*.test.ts` under Bun (GPU ones skip without a GPU or with `EDIT_NO_GPU=1`); `just native-compiled` checks the addon embedded in `bun build --compile` (re-sign with `codesign -s - -f` after compiling: Bun leaves the signature invalid). A napi `cdylib` can't link into a normal binary, which is why the engine is its own rlib.
- `packages/edit-types` (`@edit/types`, what the server and the UI type the project with) — the project model and the engine's options as TypeScript, generated by ts-rs (`ts` feature on edit-core and edit-engine) into `src/generated` by `just types` (i64 as `number`; fields serde leaves out are `?:`); committed, and `just check` fails if they don't match the Rust.
- `apps/server` — the server, on Bun: `edit` / `edit app` opens the editor in a window (`window.ts` extracts and runs `crates/edit-window`; links out open in the browser; WKWebView has no `window.confirm`/`alert`, so don't use them in the UI, and its WebGPU validates more strictly than Chrome's: a viewport outside the target drops the whole frame), and `edit serve` is the same thing headless: REST + websocket events, FFmpeg media jobs, native frame renders through the addon, export, MCP at `/mcp` (`?project=` scopes a connection to one project), and `agent.ts`, the agent panel's bridge to one of two providers: Claude Code, the only one the UI offers (Oct 24: Codex is hidden; Edit picks the model and thinking level, the panel sends none, so a turn without one runs on `claude.DEFAULT_MODEL`; a caller naming a model, the teaching loop's `round.py`, gets it for that turn and Edit's retries; `POST /api/agent/provider` can still switch to Codex until Edit restarts) (`claude.ts`: the user's own installed `claude` driven through Anthropic's Agent SDK, signed in by the user with `claude auth login` on their own plan or API key; Edit never touches the sign-in, which is what Anthropic's terms allow; one `query` per turn resuming the project's session, no built-in tools, none of the user's settings, hooks or MCP servers, Edit's MCP pre-approved, compacting near 150k tokens), or Codex through `codex app-server`. A chat started on one provider starts a new conversation on the other. Edit ends a turn itself when its agent can't: a stop not answered in 15 s, 25 minutes without a word (tools give up at 15), or Edit quitting (SIGINT or SIGTERM: Claude Code closed, Codex stopped, the chat saying so; running turns are noted in `<home>/agent/running-turns.json` as they start and end and every minute, so a quit or a crash leaves the ones it cut, and when Edit is back within 10 minutes, a restart, each carries on as a new turn of the same conversation, so restarting the dev server for a new build never costs an agent its task); Codex going away ends only Codex's turns, and a Claude session Claude Code no longer has is started again as a new conversation in the same turn. `ask` takes a model: a Claude one (`claude-…`) goes through Claude Code, text only (`claude.ask`: no tools, no session kept, structured output for the schema; speakers.ts names voices with `claude-sonnet-5-5`), any other through Codex (captions.ts's watcher: `gpt-6-luna` with sound and pictures). `main.ts` → `cli.ts` (the `edit` command), `serve.ts` (binds, Tailscale, the App, every package's tools and routes, cloud start/shutdown), `routes.ts` (the generic handlers and `buildRouter`, which puts every package's routes in), `http/` (router, files with ranges and 304s, compression). The addon's contract is `src/native/index.ts` (`stub.ts` stands in for tests without `crates/edit-native` built; it is not the engine). Packages reach each other only through `src/seams.ts`. Live projects are frozen: `store.checkout` or `store.update` to change one. MCP: `src/mcp/tools.json` declares every tool (names, descriptions, schemas) and `instructions.ts` is the core house style; a package's tools register when its module is imported (`registerEditingTools()` in `edit_tools.ts`, `registerMediaTools()` in `media_tools.ts`, the rest as the seams load) and its routes go on the router through its `routes(router)`. Read tool arguments into model types with `clips.ts` / `serde.ts` (serde's defaults, f32 rounding and error words) and write numbers and strings into agent text with `rust.ts` (`round` half away from zero, `fixed` for `{:.N}` with ties to even, `f32Saved` for an f32 as saved, `{:?}` quotes; project files and caches are still written by edit-core, so these keep its formatting). Google calls go through curl with the sign-in on stdin, or fetch with redirects followed by hand so a Google call never leaves https; files broll makes are named by `hash.ts` `fingerprint` (pinned by a test, so caches stay valid). A release's entry is `src/embedded.gen.ts`, written by `scripts/embed.ts` (the UI, the addon and the window helper inside the binary; gitignored); `bun build … --compile` then `codesign -s - -f`. `test/mocks/` stands in for every outside service: `server.ts` (relay, AI Gateway, Google; `mock.doc` / `mock.driveFile`) and `cloud.ts` (the relay's `/v1/cloud/*`, R2 behind presigned URLs and Convex in memory). A media whose path becomes its cloud proxy takes its analysis along (`carryAnalysis`): the watcher's answers are named by the media key, so the older keys are listed in `watch/keys.json` (`watch.ts` `otherKeys`), which goes to the cloud with the rest. Checks: `bun run --cwd apps/server typecheck` and `test`.
- `apps/server/src/writer/`, `apps/web/src/writer/`, `packages/edit-types/src/writer.ts` — **Script mode**: Writer, merged in Oct 29 2026 (`docs/writer.md` is how it works; `docs/plans/2026-10-29-writer-into-edit.md` the checklist). Home's Scripts tab and `/scripts`; a script's Start the edit makes its Edit project on this Mac (`writer_handoff.ts`), and its recordings and words go to Edit's originals and analysis after import (`writer/handoff.ts`), so Edit mode neither downloads nor hears them again. Its data stays Writer's (Convex `writer:*`, R2 `writer/scripts/<id>/`, through the relay's `/v1/cloud/writer/*`, `apps/relay/src/writer_cloud.ts`), so the old Writer app works on the same scripts; the first start copies the Mac's Writer folder in (`writer/index.ts`). Permissions are Writer's ids (`scripts.*`, `review.*`) on Edit's accounts (`writer/can.ts`). Everything else it needs is Edit's: Claude (`writer/claude.ts` over `claude.ts`), hearing, watching, YouTube, research, Drive and Docs (the team Google sign-in), logs (`[writer]`), remote support. Repack's script guides and the house rules are `agent/writer/`, word for word.
- `scripts/cloud-sweep.ts` — footage in R2 no cloud project, script or local project uses (a deleted project's: Convex deletes only its body) and temporary pieces left behind. Report only by default; `--delete` deletes only what's been unused at every run for 14 days (noted in `edit/sweep/unreferenced.json`) and temporary pieces over 2 days old. Run by hand under `infisical run … --path=/edit-relay`; it touches nothing outside `edit/` (the bucket is Repack's too).
- `assets/sfx/` — sound effects compiled into the `edit` binary (`apps/server/src/sfx.ts`), so every install has them; written on first use to `~/.edit/sfx/<name>-<hash>.wav` (a new version is a new file, so old projects keep theirs). Each ships with a "hit" marker (media markers) that `add_sound_effect` lines up on the cut. `shutter.wav` is the first shutter from https://youtu.be/R24UqkKj90w, trimmed to 0.17 s.
- `apps/server/src/library.ts` — the team's sound library: the "Music & SFX Library" folder in Google Drive is the source of truth (a folder per category under Music / Sound effects, plus an index .txt of per-file notes and a usage-guide Doc). Edit lists it through the Drive API and downloads a sound on first use to `~/.edit/library/<music|sfx>/<checksum>/`; nothing is bundled. Its Google sign-in comes from the relay (`/v1/cloud/google/token`, a short-lived access token for Edits with the cloud token), unless `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET` and `GOOGLE_DOCS_REFRESH_TOKEN` are set on the machine (`just dev` borrows Repack's from Infisical); Docs imports, Drive links and Drive uploads share it. The agent's `list_library` / `add_from_library` use it (the UI's Library tab went Oct 24). A sound it places is tagged `media.library` (`music` / `sfx`): a cloud copy's path (the cache's `originals/sha256/…`) no longer says `library/`, and untagged music had been sorted as speech and transcribed; `tagSounds` tags older projects on open by file name against the listing, and the cloud repoint keeps the tag a library path implies. One download per file at a time (a second ask waits for it); curl gives up on a stalled one, so it's retried rather than held forever.
- `crates/edit-engine/src/loudness.rs` — every measurement of sound (`library.levels` / `loudness`: `measure_audio`, `set_loudness`, `add_from_library`'s `loudness` and `under_speech`, voice-over levels) is arithmetic over the file's analysis: one FFmpeg decode makes 10 ms blocks of K-weighted energy and sample peak, kept as `<cache>/<media key>/loudness-v1.bin` (the media key covers size and mtime, so a changed file is analysed again) and in memory. It matches FFmpeg's `ebur128` (padded with 0.5 s of silence) within 0.5 LU (`matches_ffmpeg_ebur128`); a new method or layout is a new file version. Imports analyse in the background; `prepare` analyses several files three at a time. `library.footageLoudness` is the edit's speech (the footage's sound, else its voice-overs), what `under_speech` counts down from.
- `apps/server/src/cutin.ts` — `cover_cut_in`: the agent picks a cut-in's B-roll shots and this lays them out the house way in one call (butted shots, push-ins, B-roll look, vertical drop, card gone, voice-over to A1). Slowed clips use native frame sampling; optical flow is opt-in (`smooth: true`; the user wants it almost always, so making it fast and automatic is speed-plan 2.2), one render at a time in a lane of its own (never the media processor's slot, so imports don't wait behind it), stopped while an export runs, and limited to 120 seconds of running per shot. Exports take the current timeline snapshot immediately unless `wait_for_smoothing` is explicitly requested.
- `apps/server/src/broll.ts` — `map_view` renders the map page in headless Chrome (one at a time on an 8 GB Mac, two with 16 GB or more: `MAP_RENDERS_AT_ONCE`). A moving shot (at most 12 s: every frame waits on tiles, 0.15–1.9 s each) answers once its first frame and building track are in and renders the rest in the background: the media is that first frame (`map-<key>-first.jpg`) until the footage swaps in under the same media id. A render is stopped only when it stalls (nothing new from the page for `mapStallMs`), never for being slow: each restart is a minute of loading and a paid session from the relay's daily allowance. Frames land whole on disk, and what was asked is kept beside them (`map-<key>.job.json`), so a render cut short carries on from them: when `map_view` is called again with the same arguments, after a restart (jobs.json kind `map`), or when an export finds the stand-in on the timeline (`waitForMaps` starts each stuck one again once, then waits). Exports wait for a map still rendering (the agent's up to 10 minutes, the UI's a few seconds) and refuse a stand-in whose render failed again or that has no job file, saying so; they never export the still by mistake. Each map keeps its job file for good and its measured JSON says the look it was drawn with (`look`): when a fix makes earlier maps wrong, raise `MAP_LOOK` and an export draws each older map on its timeline again (`redoOutdatedMaps`: same media id, place labels moved by how far the building moved, `repinLabels`); maps from before job files existed (Oct 21) can't be. The page grades on the GPU (a post-process stage) and draws close views at 1x, wide ones (range ≥ 500 m) at 1.5x against shimmer; most of a frame is the GPU drawing it (the read back), and each map's JSON has `spent`, its time by stage. `track_region` (`crates/edit-engine/src/track.rs`) template-matches small greyscale frames (the box ~40 px wide; the light preview when frames are looked at ≤640 wide, else the original, so a small face in a zoomed-in shot isn't blurred by the preview; AVFoundation on macOS, FFmpeg otherwise) at the footage's rate for stretches up to 40 s, 15 fps beyond; each frame the box is first carried by the camera's move (`motion.rs`: shift, turn and zoom fitted to a grid of patches, cuts detected), searched coarse to fine to a fraction of a pixel with a centre-weighted template (less weight on the wall behind a face), held to the box as given against drift, lost when matches are weak (it rides with the camera; reported), looked for anywhere after a cut (confirmed by the next frame). `boxes` adds sightings: passes run from each to the next, their drift is spread back so they meet each sighting, and they're blended; the path is smoothed by a centred local line fit (no lag), never across a cut. Positions go through the footage's keyframed framing (a push-in), which the static transform missed. Frames are kept a few minutes for another pass; coordinates stay in source pixels. `real_bench_face` (ignored; `EDIT_TRACK_REAL`) measures it on Mom & Teen's bench shot.
- `apps/server/src/edit_plan.ts` — `apply_edit_plan` applies a whole stage in memory (times in frames; `add` needs start and duration; `transition`, `evidence_board`, `date_title` and `place_label` build house graphics in one line (`graphics.ts` has the last two: the date cut-in's date is white with only a drop shadow over a darkening adjustment, never boxed or glowing; the map's place label is the house label pinned to `building_track`; `cover_cut_in` puts every picture shot on the Windows screen, so a found photo is never plain B-roll): an evidence board is framed photos (video clips' `frame`: border and drop shadow) on paper, the camera in one continuous glide past them (each photo centred at its `at`, the frame of the word naming it; a smooth S whose speed eases to ~70% of its average at each photo and picks up between, never stopping) and red notes in Reenie Beanie writing on; each photo's `at` is marked ("board photo") and gets a quiet bundled shutter whose click lands on it, unless `shutters: false` or another shutter is within 8 frames; `title_collage` is a courtroom compilation's title card (its title starts "When…"): one framed photo per case, a row above and a row below, the title in big glowing capitals between them over a darkened courtroom (`graphics.ts`); `markers` as the markers tool; moving or deleting one half of a linked pair takes the other along unless `unlinked`), resolves named references, validates the final project and commits once with `base_rev`; an invalid/stale plan saves nothing, except that a plan on a revision the agent was shown still saves when only background work (a cloud upload, a smoothed shot or map swapped in) changed `media` since (`edit_tools.onlyMediaChanged`). Its `audit` is the mechanical review (picture gaps, slivers, bare cut-in cards, exhausted sources, misaligned linked sound, review notes like "[unclear]" left in on-screen text, the same B-roll moment in two places, transitions with no sound, a subtitle past its cut, footage under 8 frames, a picture on screen outside a designed graphic (`bare_still`, `letterboxed`), a boxed or glowing date (`date_style`), words on a track under a blur over them (`text_under_blur`: a redaction above a label blurs it); and, where the MCP side adds what needs the media cache: B-roll that's mostly pixelated or blurred, `censored_broll`, and quote callouts off the words that point to them, `callout_off_speech`, from `edit_review.calloutTiming`), so the agent renders only for judgement. The plan's house pictures and sounds (the board shutter, the desktop's wallpaper and windows) are added to the plan's own copy of the project first (`edit_tools.planAssets`, `import.houseMedia`), so it still saves once or not at all. A plan that adds or relabels text ends with `people.oneColourPerPerson`. Begin with `get_edit_context`: one line per clip, cut-in words as `word@seconds`, narrowed by `section` (intro / story / outro) or start/end, capped near 36k characters (Codex truncates tool output at ~10k tokens). `find_in_footage` (`footage_search.ts`) searches every footage transcript for many phrases in one call (B-roll candidates). `batch` runs independent lookups three at a time. Its `transition` op builds drop, flash, dip and open, and two styles' own: `light_leak` (courtroom: 16 frames of warm light sweeping across and burning to white on the cut) and `burn` (interrogation's "Bridge flash": 12 frames burning out warm), both on the adjustment's `grade.leak` / `leak_x` (the renderer's light leak, `adjust.wgsl`: warm light added from one side, orange where faint, white where strong; keyframable); the audit never calls them repetitive but wants each heard.
- `apps/server/src/intro_graphics.ts` — the interrogation intro's house graphics, one plan op each, learnt from Red Thread Interrogations and Red File (docs/feedback/2026-10-19-interrogation-intro.md): `intro_captions` (the teasers' subtitles restyled: boxed lines coming up word by word, white on black, the lines that matter on red, naming nobody so the role colours don't apply; `edit_tools.hearWords` fills in the frames words are heard at), `countdown` (one text clip a second), `fast_forward` (a keyed glitch and "FF >>"), `disclaimer` (the house's own words), `text_slam` and `timeline_bar` (Red File's: the line is the second year's leader); plus edit_plan's `red_flash` transition and date_title's `position: "bottom"` with `place`.
- `apps/server/src/reset.ts` — `reset_edit` ("reset the video", Oct 24): the edit back to the script import's first layout (every clip, timeline marker, in/out, segment and the cast gone; the script laid out again by `script.layOut`; the voice-over takes put back by `voiceover.generate`, which reuses the takes spoken), so a project can be edited again from the start with what the agent has learnt since. The tool never acts alone: it asks in the chat (a `reset` event, `GET/POST /api/projects/{id}/reset`, the agent panel's Accept / Reject card) and waits up to 10 minutes; the edit before is written to `projects/history/<id>/` first. Blocked in review-fix turns.
- `apps/server/src/review.ts` — `read_review`: a Frame.io share's comments (headless Chrome on its print view) placed on the timeline with the clips at each, for the `feedback` skill. `revoice_cut_in` (`voiceover.revoice`) speaks one cut-in again (a word fixed) and fits the take to the cut-in by speed (0.85–1.2), so nothing moves; with no voice project here (made on another machine) it starts one from the script's lines.
- `apps/server/src/markers.ts` — marked moments to plan sounds on: on a media at source seconds (`Marker {time, name, note}`, so they move with every clip of that moment) or on the timeline (`Project::markers`, frames, carried by ripples). The `markers` tool / plan op adds, removes and lists them; `add_sound_effect` / `add_from_library` take `markers: [name]`; `get_edit_context` lists them in its span. A sound's own "hit" is never listed or removed by name alone. The ruler shows timeline markers as amber flags.
- `crates/edit-engine/src/censor.rs` — redacted footage: each file read once (the light preview's keyframes, a 128×72 grey frame a second; one at a time in the background, started when the file's preview is made and by the audit, paused while an export runs) and every second judged by how flat it is (≥78% of neighbouring pixels within 2 levels, mean difference ≤3.5, contrast kept); `<cache>/<media key>/censor-v1.bin`, one byte a second. B-roll with ≥60% of its seconds censored is `censored_broll`; files not read yet are `censor_check_pending`. `EDIT_AUDIT_PROJECT=<path> bun test test/edit_review.test.ts` (in `apps/server`) audits a real project read-only.
- `crates/edit-engine/src/screen_text.rs` and `apps/server/src/onscreen.ts` — what the audit reads off the picture. Words on screen: Vision's text recognition (`mac_media::text`, the fast level) on the light preview at 960 wide, one frame a second of the seconds the timeline plays, cached as `<cache>/<media key>/text-v1.json` (~0.1 s a frame); another channel's call to action ("SUBSCRIBE", the bell) not under a rect blur is `source_cta`, with the box to blur in project pixels. A B-roll shot (a clip named "…B-roll…") across a cut in its footage (`seats.cutsOf`: the camera-angle frames' scene starts, `cuts-v1.json`) is `broll_crosses_cut`. Both read in the background when the audit asks and are `picture_check_pending` until done. The rest of Corrupt Cop's round is TS: `cut_mid_word` (footage sound cut inside a word, `edit_review.cutMidWord`), `profile_line_off_speech` (a desktop profile's line away from the narration saying it; `edit_tools.timeProfileLines` times them from the narration by default) and the courtroom's `small_text` (callouts and tags under 60 px at 1080p, `edit_plan.audit`).
- `crates/edit-engine/src/mac_media.m` / `mac_media.rs` (compiled and linked by edit-engine's `build.rs`) — macOS AVFoundation video and sound readers, bounded pixel-buffer writers and an AAC writer, ImageIO still-image decoding and encoding (JPEG for agents), and Accelerate pixel conversion and scaling. Standard hardware H.264/HEVC exports and preview video transcoding use them; the compositor is still `edit-render`. FFmpeg handles nonstandard export options, other speeds' sound (atempo), explicit optical flow, and compatibility decoding. `EDIT_FFMPEG_VIDEO=1` / `EDIT_FFMPEG_AUDIO=1` select the compatibility backends for diagnosis. Photos stay images on macOS; do not encode them into 30-second videos.
- Share (Oct 24, replaces the editor's Export button and dialog): `ShareDialog` → `POST /api/projects/{id}/share` → `reviews.exportAndShare`: the house export of the whole edit (kept on disk, `keepLocal`), then `reviews.share` puts it on the project's Repack review link (made the first time, a new version under it after); it runs on with the dialog closed, the review's `sharing` saying how far it is. The agent's `export` and `share_for_review` tools are unchanged.
- Exports (`crates/edit-engine/src/render.rs`; the server's `exports.ts` runs one at a time here, any number in the cloud, and sends the events): the sound is mixed first in Rust (`mix.rs`: each clip's stretch decoded on its own, a few seconds' window at a time; loudness: the gain that reaches the target, measured again after a look-ahead limiter that holds peaks under -1 dBTP), then the picture runs as a pipeline (planner → three decoder threads, one reader each, jump cuts sent to the one already in that file → compositor with readbacks in flight → encoder thread), and FFmpeg joins picture, sound and chapters without re-encoding. Don't run AVFoundation sound reads beside the picture's decoders: they contend (~30× slower). Background FFmpeg (previews and proxies through the engine's `run_background`, smoothing through broll's runner) is stopped (SIGSTOP) while an export holds the foreground and continued after, so it never takes the hardware encoder or the CPU from an export. Frames stay BGRA from decoder to GPU. The log line "frames composited in …; waited … on decoding, … on encoding" says which stage limits an export. Standard Mac exports (H.264/HEVC, the project's size and rate, hardware) are chunked (`crates/edit-engine/src/chunks.rs`, `render::export_file`): chunks named by what's on screen (scene per frame without clip ids, media by content, picture settings, `EDIT_RENDER_SOURCE` from build.rs: a hash of the code that draws and encodes, so a code change never reuses an old chunk), boundaries at cuts chosen by content, the file joined by FFmpeg's concat (only the picture stream declared: the old file's AAC priming would shift it) and counted frame for frame; a re-export copies unchanged chunks and the unchanged sound out of the last export (`<cache>/export-chunks/<project>/manifest-v1.json`), and an export that stopped carries on from the chunks it finished. The sound reused from the last export is keyed by `EDIT_SOUND_SOURCE` (build.rs: the mixer's code), so a mixer fix remixes it. A sound that can't be decoded fails the export, never silence in it; a cancel kills the export's FFmpeg decoders (`util::killed_on_cancel`), and reads from R2 give up after 30 s without data (`-rw_timeout`). Anything wrong with the chunked path falls back to a whole export. `export_file` takes `sounds` (media id → a local copy of its sound, `cloud_media.soundCopy`), mixed instead of a cloud original's URL. Agent renders (`render_for_agent`) go ahead of the UI's, decode a sheet's pictures side by side at the size shown, and return JPEG.
- Cloud exports on Modal (`modal_exports.ts`, on with `EDIT_MODAL_EXPORTS=1` and `EDIT_WORKER_ROOT`=this `app/`, both set by `just dev`): the house export of a whole edit whose footage is all in the cloud (H.264 with sound, the project's size and rate, no chapters; waveforms too: `edit-worker` makes their `peaks.bin` from the originals before a section renders; `unsuitable` says why not, and that one exports here) goes there when it's worth it (`cloudBetter`): this Mac is already exporting, its load is over 0.75 a core, or it would take over six minutes here (an edit at ~45 frames/s, subtitles at ~150; a cloud export spends 2–3 min around its frames, so Cop Father's subtitles took 5:05 there and 3:29 here); else it exports here, for free. It runs `apps/worker/export_v3.py` under `infisical run` (the team's project, `/media`: R2's keys for that process only; Infisical's CLI signed in on the Mac, no Repack checkout needed). The driver presigns the originals and 128 upload parts, deploys `edit-exports-v3` (`apps/worker/sections_v3.py`) when this checkout's worker build isn't the deployed one (`~/.edit/modal/`, one deploy at a time), and spawns a coordinator: eight sections on a pool of eight L40S shared by every export, the sound on its CPU, every frame of the joined file decoded on sixteen CPU verifiers, then published to R2, copied here, SHA-256 checked and removed from R2. Sources, sections and sounds stay in the `edit-exports-sections-v3-live` volume (pruned after 14 days unused), so an export after a small change renders only the sections it touched. Progress comes from a Modal Dict; a cancel (a file beside the job, and SIGTERM) or the server going away stops its Modal work. NTSC rates run at their real rate (`sections_runtime.rate`). Drive: a whole subtitled video uploads unless the export says `drive: false` (the dialog's switch, the export tool's `drive`); `drive: true` uploads any whole video export (a normal edit to Render).

Every write goes through `Store.commit` → `Cloud.mayWrite`: a project someone else holds is refused (HTTP 423, the agent gets the reason); one not asked about yet takes the lock first (blocking, once); unreachable, writes are allowed and queued. Losing the lock with unpushed changes, or a `conflict`, keeps this machine's version as "<name> (conflicted copy)" (local only) and takes the cloud's — never an overwrite. The editor calls `POST /api/projects/{id}/cloud/open` before loading (downloads a cloud-only project and answers; `cloud_media.ensureLocal` fetches its footage behind it), shows a read-only banner with Take over (force), and refreshes when the holder lets go. ## Building the dev server

The long-running server (`/tmp/run/edit`, started by `/tmp/run/serve.sh` on :7700) is built with `just serve-build` (UI + native addon + `bun build --compile`; `just serve-build-bin` skips the UI). The addon builds in `[profile.serve]` (release opt-level 3 everywhere, but no LTO, 256 codegen units, incremental, unstripped) with target and build dirs on the internal SSD at `~/edit-build/{target,build}` (`EDIT_BUILD_DIR` overrides), and the binary is swapped into `/tmp/run/edit` by rename (`EDIT_SERVE_BIN` overrides), so the running server is safe; restart it yourself when nothing is exporting. A TS-only change needs no Rust build; a change reaching edit-core/edit-render/edit-engine rebuilds the addon. A change to edit-core or edit-render also changes the page's engine (WASM, `just wasm`; the dev UI on :5173 reads `apps/web/src/engine/pkg`, :7700 embeds `apps/web/dist`): `serve-build-bin` builds the UI again when they or the UI changed since `apps/web/dist` was built, because a page whose engine checks projects with older rules than the server's refuses them (Mom Leaves 5 Kids showed black throughout after people's white bystanders were allowed); the preview says so when it does. Don't put Rust build dirs on the LaCie (a spinning disk) or share one build dir between checkouts building at once. While an export runs, build with `CARGO_BUILD_JOBS=2` so it isn't starved. `just release`, `just publish` and CI keep `[profile.release]` (thin LTO, stripped).

## Releases and self-update

Claude Code maintenance (`apps/server/src/claude_support.ts`) runs once on the first start of each installed nightly, recorded before it begins in `<home>/agent/claude-support.json`, never on every launch. It updates the user's own CLI, diagnoses installation and credential sources, verifies a real `claude -p` request and the Agent SDK connection, and lets the CLI own browser sign-in. Auth failures retain the user's message in `agent/claude-pending.json` and resume it once after verification; Stop, New Chat, a newer message or a provider change cancels the retry, and the cloud lock is checked again. Report only scrubbed diagnostics; never store tokens or authorization URLs. Packaging's smoke start sets `EDIT_CLAUDE_MAINTENANCE=0`. See `docs/claude-setup.md` at the repo root.

Remote support (`apps/server/src/remote_support.ts`, `remote_actions.ts`; Convex's `editSupport` in Repack): every signed-in Edit registers its device, and an admin sends it commands from their own Mac with `edit remote devices`, then `edit remote update <device>` (install the newest build), `edit remote diagnostics <device>` (a problem report, `GET /api/reports`, that leads with what needs attention: a nearly full disk, nobody signed in, the relay not answering, setup not ready, imports and syncs that stopped, agent turns quiet 15 minutes; then the machine, the work under way, every recurring warning and error of the last two days grouped with its count and latest example, the projects, the scripts, timings and the end of the log; `GET /api/remote-support/report` shows this Mac's own), `edit remote resume <device> <project-or-script>` (a project only on that Mac goes to the cloud, then an unfinished import starts again), `edit remote unstick <device>` (syncs waiting out a failure tried again, stopped imports of projects and scripts started again, agent turns quiet 15 minutes stopped, the cache cleaned on a nearly full disk) or `edit remote restart <device>` (Edit started again in place, refused while an export, an import, Claude on a script or an agent turn would be cut off). unstick and restart ride on resume (reserved targets in `remote_actions.ts`), so Repack's Convex knows only update, diagnostics and resume. None of them runs the agent. To fix something found in a report: fix it in code, ship a nightly, then `edit remote update <device>`. `edit remote history <device>` says how each went. A device asks only for the kinds it carries out (`pending`'s `kinds`), so builds from before diagnostics and resume still get updates alone.

Builds are named by their tag everywhere ("edit v0.0.0", "edit nightly-1": `edit --version`, Settings, the update pill, release titles). Versions go up a patch at a time (v0.0.0 was the first, then v0.0.1, …), never minor or major. **Never move to a new version (`just publish`) unless the user says so**, each time: an agent ships nightlies, not versions. In between are **nightlies**: `just nightly` (everything committed on `main`) tags main's head `nightly-<N>` (the next number) and pushes; the workflow builds it like a release with `--define EDIT_NIGHTLY=<N>` (`apps/server/src/version.ts`: `BUILD` is then "nightly-N", what the editor and `edit --version` show) and publishes it as a GitHub pre-release, so `releases/latest` (Stable, `install.sh`) never sees it. With everything committed on `main`, `just publish` runs the checks, releases the current version if it was never tagged, otherwise bumps the patch in `Cargo.toml` / `Cargo.lock` / `apps/web/package.json` / `apps/server/package.json` (committed as "Release vX.Y.Z"), and pushes it with its `vX.Y.Z` tag. `.github/workflows/release.yml` then builds the UI once, builds `edit-<target>.tar.gz` (+ `.sha256`) for `aarch64-apple-darwin` (Apple Silicon only: the Intel build was dropped Oct 29, the whole team is on Apple Silicon; an Intel install finds no asset and offers no update), and publishes the draft release when it's up. Running the workflow by hand makes a test build (workflow artifacts, no release). Each build also makes **Edit.app** (`scripts/package-app.sh`: the Tauri window with `edit`, `edit-ffmpeg` and `edit-ffprobe` in its Resources), its update zip `Edit-<target>.zip` (+ `.sha256`) and the disk image people install from, `Edit-Apple-Silicon.dmg` (`scripts/make-dmg.sh`: dmgbuild lays out the window, `scripts/dmg/background.swift` draws it; Finder writes names in dark grey over a picture, so each sits on a light tag, and never set dmgbuild's `hide_extensions`: its Finder info breaks the app's strict signature check). With the repo secrets `MACOS_CERTIFICATE` (Developer ID Application .p12, base64) and `MACOS_CERTIFICATE_PASSWORD` everything is signed with the Developer ID under the hardened runtime (`scripts/dmg/edit.entitlements`: Bun's JIT and its unpacked addon); with `NOTARY_KEY` (App Store Connect API .p8, base64), `NOTARY_KEY_ID` and `NOTARY_ISSUER` the disk image is notarised and stapled; without them it's all ad hoc. Once signed, `package-app.sh` starts the app's `edit` (`--version`, then `serve` until `/api/health` answers) and fails the build before the disk image if it doesn't: a Bun-compiled binary can hang at start under the hardened runtime, which no earlier step shows (Writer's did with Bun 1.4.4, Oct 23). CI's Bun is pinned (`bun-version` in release.yml, 1.4.0, the version Edit is built with here); move it only after a signed build of the new one passes that check. An Edit running inside Edit.app updates from the zip and replaces the whole app (`update.installApp`: unpacked beside it, signature checked, same team, two renames; files inside a signed app are never swapped), then execs the new app's server at the same path; the window carries on until Edit is next opened. Adding a target means a matrix entry plus `install.sh` and `assetTarget()` in `apps/server/src/update.ts`; removing one breaks updates for that platform.

The repo is public: installs read GitHub Releases directly, no token. `install.sh` (`curl -fsSL https://raw.githubusercontent.com/spheceo/edit/main/install.sh | sh`) fetches the latest release's archive (`EDIT_VERSION=v0.0.N` or `nightly-N` for a pinned install or a rollback, `EDIT_VERSION=nightly` for the newest nightly) and puts every program in it beside `edit`. `apps/server/src/update.ts` checks GitHub on the install's channel (Settings → Updates, kept in `<home>/update.json`): Nightly, the default, offers whichever release or nightly was published last (a nightly ahead by its number, a release by its version), Stable only `releases/latest`, and never a downgrade (a nightly you're on waits for the next release). The editor's "Update to nightly-N" / "Update to vX" button (`apps/web/src/lib/update.ts`) downloads, verifies, swaps in every program in the archive (executables at its top, `edit` last; so a later release can add a window helper or an addon and older installs pick it up) and execs it in place; the page reloads when the new version answers. Only builds compiled with `--define EDIT_RELEASE=true` (the release workflow) update themselves, so dev builds never replace themselves.
