# The server in Effect, where the same bugs keep coming back

Sphe, Nov 1: after Mathias's two FOIA scripts stopped at "transcription failed (413)" (a 4 h 39 min and a 5 h interview, each import ~41 min before it failed and then resumed 13 times), "if the import stage was written in Effect… would we have prevented this?", then "look at the last maybe 400 commits… which were bug fixes that we came back to more than once, and rewrite those parts of the code in best practice Effect. take your time with the rewrite."

The answer to the first question was: not the mismatch itself (the client sends a whole file at 32 kbps, the relay caps a request at 45 MB, nobody joined the two numbers), but everything around it: the error would have been a type the import had to handle, retries would never have been offered for an error that can't change, the pieces would have been interrupted when the whole hearing failed, and the trace would have said which step took the 41 minutes.

## How the rewrite is done

- Effect 4 (`effect@4.1.1`, `@effect/platform-bun@4.1.1`), written as the package's own AGENTS.md teaches: `Effect.fn("name")` for functions, `Schema.TaggedError` for every failure, `Context.Service` / `Context.Reference` for what a part needs, `Schedule` for every retry, `Effect.forEach({ concurrency })` / `Semaphore` for "N at once", `Scope` and `effect/process` for child processes, so interrupting the work kills its processes.
- Part by part, inside the module, keeping its exported Promise functions with the same names, arguments, results and error messages, so callers (and their tests) don't change. Effect stops at that boundary until the callers are rewritten too; then the facade goes.
- One runtime for the server (`src/effect/runtime.ts`): the platform layer and a logger that writes Effect's logs through `diag`, so lines keep landing in `edit.log` and the problem reports.
- Every error says whether asking again can help (`retryable`). The Promise boundary turns it into the same `Error` text the UI and the log have always shown, so the UI can stop offering Retry for an error that can't change (part 6).
- Each part: the rewrite, the module's tests passing unchanged (plus tests for what was the bug), `just check`, one commit.

## Order

1. **Transcription**, with Nov 1's fix: errors typed (busy, gateway down, unreachable, allowance used up, too long for one request, refused, extract failed); one retry schedule per kind; the pieces and the whole hearing run together and either failing interrupts the other (and kills its FFmpeg); the whole hearing is encoded at a bitrate that fits the relay's limit (a test reads the limit from `wrangler.toml`, so the two can't drift again), and a file too long even for that keeps its words from the pieces and goes without voices rather than stop the import.
2. **Sign-in renewal**: the renewal policy as one `Schedule`, the token refusals as typed errors.
3. **Child processes**: one `Proc` service (`effect/process`), every FFmpeg/FFprobe/yt-dlp of parts 1, 3 and 6 through it, owned by a scope; limits as semaphores.
4. **Downloads**: the route ladder as data, failures typed as "the video is gone" (stop) or "this route failed" (next route).
5. **Script cloud sync**: one script's failure is that script's state, said once, not a warning each pass; the loop is a supervised fiber.
6. **Script import**: steps as Effects with typed failures; Retry offered only when the failure is retryable; resume never re-runs a finished step.
7. **Exports, shares, archives**: a file being read is held by a scoped lease; an archive waits for the leases.

## Done

- Part 1, transcription: `src/effect/runtime.ts` (the runtime, logs through diag), `src/effect/proc.ts` (scoped child processes), `src/transcribe.ts` rewritten; written up in `docs/feedback/2026-11-01-mathias-foia.md`.
- Part 2, sign-in renewal: `src/accounts.ts`'s timers, `TryLater` and failure counter replaced by typed errors, `renewalRetries` and one `renewer` fiber; `effect/runtime.ts` `idle` for waits that mustn't hold the process.
- Part 3, child processes: `src/writer/proc.ts` (every FFmpeg, FFprobe and yt-dlp of Script mode) runs each program in its own process group owned by a scope, so a stop, a deadline or a failure ends the whole group. The old runner killed only the program: a stopped yt-dlp's FFmpeg kept going, and while a child held the output open the stop itself didn't return (`test/writer/proc.test.ts`: 30 s against the old runner, at once now). Transcription's processes went the same way in part 1 (`src/effect/proc.ts`). Not rewritten: the audit's and frame scans' limits (897fbeef, 224ab730) already go through `media.ts`'s semaphore and have held since; the other ~30 modules' `Bun.spawn`s move to `effect/proc.ts` as their parts are rewritten.
