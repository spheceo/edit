# Edit V2: the agent writes the graphics as code

Started Nov 10 2026. Sphe: "This is a huge thing… we want to build out and see to the very end." The in-app agent writes each graphic (and later each sound) as code, the person watches it play the moment it's written, steers it in a few words ("add a shake"), and what's made is kept in a library every project and teammate draws on and improves. The team saw two effects made this way outside Edit (Dr Insanity's evidence windows and evidence board, recreated by measurement) and approved the direction.

What matters most, in Sphe's order: playback is instant; the system improves itself (he no longer trains agents by hand); the quality the team already has.

## Decided (Sphe, Nov 10)

- **Instant playback first.** The live preview is built and proven before the render.
- **A beta switch.** Settings → Beta → Edit V2; with it on, New project offers Bodycam HQ after Bodycam, "and that will purely use this new system". Everything else stays as it is.
- **Code over tool calls.** "If you have to choose between the agent writing code or the agent running a tool call, choose the writing of code, as much as possible, so that the agent has full control." Tool calls where code makes no sense (he named making cuts).
- **Our own versioning, not Git.** Templates (the evidence board, say) live in the cloud. A project that uses one keeps the exact version it used; a later change is a new version and old projects keep theirs; the agent can look back at older versions and what differs, only when needed.
- **Teaching.** A "teacher" permission, admins have it by default. A teacher talks to the agent; being taught both uploads new code and updates the agent's own skill file. Where what it's told contradicts what it was taught, it stops and asks which one sticks.
- The library starts with effects; skills follow through the teacher flow.

## How it works

An effect is a folder of code among the project's media, `<home>/media/<project>/effects/<name>/scene.html`, a page that draws any moment on request: `window.duration`, `window.ready`, `window.seek(t)`, the same `t` always the same pixels. Playing it is asking for the playhead's moment, so nothing is rendered to watch it, and its length costs nothing.

- **A project made the new way** is `Project::hq` (its style stays the kind of video, so permissions, narration and audits are bodycam's). An effect on the timeline is a media with `Media::effect` (the folder's name) and ordinary video clips of it: placed, moved and cut like footage. What the engine plays for it is a still until the render exists.
- **The agent writes the code itself**, with Claude Code's own file tools (Read, Write, Edit, Glob, Grep) running in the project's effects folder and allowed nowhere else; no shell. Three tools do what code can't from there: `look_at_effect` (stills, a frame's cost, what the page gets wrong), `effect_picture` (one of the project's pictures into the folder) and `add_effect` (the effect among the media). Its teaching is `agent/hq/notes.md`.
- **The viewer plays the page itself**, in a frame over the picture, told the playhead's moment (`EffectLayer.tsx`). A save is on screen as it lands (the server watches the folder).
- **The page is shut in**, since its code is the agent's: no origin (no cookies, no storage, no way to the page around it), no network, nothing loaded from outside its own folder, and the server refuses it every route but its own files, which are under a key in the address.
- **The editor of an HQ project** is the viewer and the chat, the viewer's bar moving through the edit.

## Measured

On mandalorian (Chrome 157, RTX 4060), the team's evidence board (DOM, CSS and SVG, a whole-frame motion blur; 1920×1080, 44 s):

| | |
|---|---|
| Played by itself, the whole 44 s | 2,625 of 2,635 frames at 60 a second, 5 late, all in the first 5 s |
| The same shut in (no origin, no network, the playhead by message) | 2,637 frames, 2 late |
| In Edit's editor page, the playhead run through 12 s of it | 722 frames drawn by the effect's page (60 a second), none late |
| Drawn on the CPU instead of the graphics card | about half the frames |
| Opening the editor to the effect on screen | 0.65 s |
| A save to the new page on screen | 0.15 s |
| The agent's look (six stills) | 1.7 s |
| A DevTools screenshot of one frame (what a render costs) | 0.6 s, with or without the graphics card |

Not measured yet: Edit.app's window on a Mac (WKWebView: Safari's engine, where the team works; a run is under way on kenobi), whether Safari's engine draws an effect as Chrome does, and an effect with moving footage in it (the board's "footage" is a still).

## Built

1. (Nov 10) The beta switch and Bodycam HQ; effects as code, served shut in; the agent's file tools and three effect tools; the live layer in the viewer; the HQ editor. An export of an edit with an effect is refused, in words, until the render exists.

## Next, in order

2. **The render.** An effect baked to a video in the background once its code settles (the map shots' pipeline made general: frames from the Chrome Edit drives, joined, swapped in under the same media id, resumed after a restart), so an HQ edit exports and shares. Then graphics over footage (frames with alpha; the Mac's decoder keeps none today).
3. **Reference study.** "This link, 2:58 to 3:18": the reference's frames at a rate, side by side with the effect's at the same moments, and the numbers (a brightness grid, an object's edges over time). Better eyes raise quality more than anything else.
4. **Sound as code.** The same contract for a sound (a function of its settings that fills samples), with `listen` and `measure_audio` pointed at it.
5. **The library.** Templates in Convex with numbered versions, a current pointer, each project pinning what it used, and a compare of two versions. This is also what takes effects to other computers: until then an effect's folder is on the computer that made it.
6. **Teaching.** The teacher permission, proposals, the contradiction question, approval before anything becomes the default.
7. The two evidence effects in the library as its first templates.
