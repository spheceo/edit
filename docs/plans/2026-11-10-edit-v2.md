# Edit V2: the agent writes the graphics as code

Started Nov 10 2026. Sphe: "This is a huge thing… we want to build out and see to the very end." The in-app agent writes each graphic (and later each sound) as code, the person watches it play the moment it's written, steers it in a few words ("add a shake"), and what's made is kept in a library every project and teammate draws on and improves. The team saw two effects made this way outside Edit (Dr Insanity's evidence windows and evidence board, recreated by measurement) and approved the direction.

What matters most, in Sphe's order: playback is instant; the system improves itself (he no longer trains agents by hand); the quality the team already has.

## Decided (Sphe, Nov 10)

- **Instant playback first.** The live preview is built and proven before the render.
- **A beta switch.** Settings → Beta → Edit V2; with it on, New project offers Bodycam HQ after Bodycam, "and that will purely use this new system". Everything else stays as it is.
- **Code over tool calls.** "If you have to choose between the agent writing code or the agent running a tool call, choose the writing of code, as much as possible, so that the agent has full control." Tool calls where code makes no sense (he named making cuts).
- **Our own versioning, not Git.** Templates (the evidence board, say) live in the cloud. A project that uses one keeps the exact version it used; a later change is a new version and old projects keep theirs; the agent can look back at older versions and what differs, only when needed.
- **Teaching.** A "teacher" permission, admins have it by default. A teacher talks to the agent; being taught both uploads new code and updates the agent's own skill file. Where what it's told contradicts what it was taught, it stops and asks which one sticks.
- The library starts with effects; skills follow through the teacher flow.

## Decided (Sphe, Nov 11)

- **V2 is for graphics.** "The main point of v2 is to improve on graphics. I don't need it to draw an image for me or create a person's voice, but I will need it to cut up clips and what not." Pictures, real footage and voices come in from outside; the agent frames and animates them, never paints them.
- **Two agents.** "A mix of an Opus agent for most stuff and a Fable 5.2 sub-agent for graphics." The chat is Opus's: the footage, the cuts, the sound, the edit. When a graphic is wanted, Opus hands it to a Fable 5.2 sub-agent (thinking high), which writes, looks at and revises the effect and hands back. Today the whole HQ chat runs on Fable 5.2 at high (19f3446c), an interim until the split is built.
- **V2's cloud.** Its code and its skills live there, not in Edit's release (see 5 below): the effects (templates and each project's own), versioned, and the skills and style rules the agent reads, so a lesson takes effect without a nightly and another computer can revise an effect it didn't make.
- **A blank start.** A Bodycam HQ project may start with no script, its footage given in the chat (a link the agent brings in whole with import_link, or files dropped in). Built (90c10b6d).
- **Controls like a video site's** over the picture (b6742cd6).
- **For now the system holds no graphics of its own.** The evidence board Sphe sent was for testing only; it isn't in Edit or shown to the agent. It becomes the first template once the library exists (7 below).

## How it works

An effect is a folder of code among the project's media, `<home>/media/<project>/effects/<name>/scene.html`, a page that draws any moment on request: `window.duration`, `window.ready`, `window.seek(t)`, the same `t` always the same pixels. Playing it is asking for the playhead's moment, so nothing is rendered to watch it, and its length costs nothing.

- **A project made the new way** is `Project::hq` (its style stays the kind of video, so permissions, narration and audits are bodycam's). An effect on the timeline is a media with `Media::effect` (the folder's name) and ordinary video clips of it: placed, moved and cut like footage. What the engine plays for it is a still until the render exists.
- **The agent writes the code itself**, with Claude Code's own file tools (Read, Write, Edit, Glob, Grep) running in the project's effects folder and allowed nowhere else; no shell. Three tools do what code can't from there: `look_at_effect` (stills, a frame's cost, what the page gets wrong), `effect_picture` (one of the project's pictures into the folder) and `add_effect` (the effect among the media). Its teaching is `agent/hq/notes.md`.
- **The viewer plays the page itself**, in a frame over the picture, told the playhead's moment (`EffectLayer.tsx`). A save is on screen as it lands (the server watches the folder).
- **The page is shut in**, since its code is the agent's: no origin (no cookies, no storage, no way to the page around it), no network, nothing loaded from outside its own folder, and the server refuses it every route but its own files, which are under a key in the address.
- **The editor of an HQ project** is the viewer and the chat, the viewer's bar moving through the edit.

## Measured

On mandalorian (Chrome 157, RTX 4060), the team's evidence board (DOM, CSS and SVG, a whole-frame motion blur; 1920×1080, 44 s):

| | |
|---|---|
| Played by itself, the whole 44 s | 2,625 of 2,635 frames at 60 a second, 5 late, all in the first 5 s |
| The same shut in (no origin, no network, the playhead by message) | 2,637 frames, 2 late |
| In Edit's editor page, the playhead run through 12 s of it | 722 frames drawn by the effect's page (60 a second), none late |
| Drawn on the CPU instead of the graphics card | about half the frames |
| Opening the editor to the effect on screen | 0.65 s |
| A save to the new page on screen | 0.15 s |
| The agent's look (six stills) | 1.7 s |
| A DevTools screenshot of one frame (what a render costs) | 0.6 s, with or without the graphics card |

On kenobi (M1, 8 GB, a 60 Hz display, the board at 0.86 scale in a 1920×928 window; the Mac busy with other agents' work throughout), the same board for its 44 s:

| | Edit.app's window (WKWebView) | Chrome |
|---|---|---|
| As written | 2,628–2,634 of 2,640 frames, 9–14 late | 2,639 of 2,640, none late (3 runs of 4) |
| With its motion blur actually drawn | 1,819–1,828 (69%); about 16 a second through the fastest move (3–6 s) | 2,640 of 2,640 |

WebKit keeps up as written only because it never draws the blur: a whole-frame SVG `feGaussianBlur` over an element whose child has `will-change: transform` is skipped on screen in WKWebView (its `takeSnapshot` does draw it). So on a Mac the live preview silently differs from the render, and a heavy filter there halves the frame rate where Chrome doesn't notice. Every other difference between the engines was small: handwriting the same width to the pixel, arrows the same, pencil notes a little softer and a few pixels off down a long note, the paper's grain coarser.

What follows from it, before the render: the agent's look measures a frame's cost in Chrome on the machine Edit runs on, which isn't what the Mac's viewer is. The viewer should measure what it draws and say so to the agent (and to the person, by playing the render where the page can't keep up), and the agent's notes should name the WebKit costs (a filter over the whole frame; `will-change` under a filter).

Not measured yet: an effect with moving footage in it (the board's "footage" is a still).

## Built

1. (Nov 10) The beta switch and Bodycam HQ; effects as code, served shut in; the agent's file tools and three effect tools; the live layer in the viewer; the HQ editor.
2. (Nov 11) The render: in the background a few seconds after the code settles, several Chromes side by side, swapped in under the same media id, so the edit exports and shares like any other, a Mac's window plays the render on its own player, and the page plays live only while its code is newer than its render. Edit's own fonts for every page. A first real trial of Edit's agent: asked for a 12 s evidence board of three photos with notes, it wrote, looked, fixed and placed it in one 175 s turn of 13 calls, and it rendered by itself; it had used a Mac-only font (now Edit's own faces) and left a note cut off by the frame at one camera position. Checked in Edit.app's window on kenobi (M1): the live page draws and plays over the native picture once its policy named its folder with a scheme (WebKit refused it otherwise: black), the render (360 frames in 34 s, 26 MB) replaces it and the window's own player plays it (191 frames in 6 s, none late), the export carries it (35–37 dB against the render) and waits while it re-renders, and a render waits for the code to settle.

A recreation by measurement, done in Edit by its own agent (Nov 11, Sphe's test on the dev server, the chat on Fable 5.2 at high): asked to recreate the first 10 s of a YouTube video (https://youtu.be/W34FDMm1nCk, a product intro: type, a ribbon, a waveform, a dark carousel of pills, a button, tabs), it brought the video in (15 s), studied ten sheets of its frames, its words and its sound, then wrote one 531-line canvas page that drew all of it in Edit's own Geist, fixed it six times and placed it with the original's sound under it. Checked afterwards: the only picture on the timeline is the effect, the original only as sound; the effect's folder is that one page, no image in it or loaded by it; side by side at 1, 3, 5, 7 and 9 s it matches (the carousel's orbs softer in the original, the carousel a little lower at 5 s). It took about 20 minutes, most of them the agent planning before it wrote a line. Its render went up to the dev cloud by itself and plays from there: the first run of V2 with the cloud on.

V2's cloud (Nov 11, Sphe: "do it"): built and on dev. Each settled version of an effect kept by itself with its files on R2 by content, an effect made elsewhere brought down, undo of an effect by its versions, templates (none yet: the evidence board waits on Sphe's word), and a teacher's versions of the agent's text read by Bodycam HQ's agent over the release's, with the teaching rule (save the code and the skill; a contradiction asks which sticks). The teacher permission is `agent.teach`. Prod needs mamagi deployed by hand and a nightly for the relay. Checked on dev: the test project's effect kept as version 1 by Sphe's computer, read back through the agent's tool.

V2's cloud, simplified (Nov 11, Sphe): versions stay, but what the agent sees is short. A search returns what's in use; older versions and anything put away ("delete it" archives) only when asked. Effects and sounds carry a category, a note and a brief on how to change them. Skills start empty: the agent keeps a line or two when told to remember, under one tiny global skill (remember briefly, keep it tidy, ask on a contradiction) it can't change or put away. Sound effects are code too (make_sound), kept and reused like effects; Bodycam HQ no longer reaches the house's sound effects (music stays). Bodycam HQ's prompt is its own (the HQ notes, 413 words; its memory; its tools), without the house's instructions or skills: 27,000 characters against a normal project's 49,000, most of it the tool list. Dev's cloud cleared and seeded: the global skill and the evidence board (Sphe's zip, with its length stated and its own loop removed) as the one effect.

The house's rules back, cut down, in V2's cloud (Nov 11, Sphe: HQ is "still using the base for editing but with much better preview, and a much better feedback system and limitless effects"; "bring them back in the cloud as significantly reduced versions and we try to pull as much of JJ's feedback on bodycam edits as possible"; "it should also use the same sfxs and music as it does now").
