# Remote device commands

Edit can receive support commands without an inbound connection to the Mac. The update receiver is implemented; remote agent turns remain disabled pending an enforceable spending limit. Rollout and use are described in `docs/remote-support.md`.

Each installation needs a stable device identity and an owner-controlled way to enable, disable and revoke support. A live, authenticated Convex query can deliver pending commands while Edit is running. Edit currently calls Convex through the relay, which keeps a shared service credential; that credential must not be given to clients. Direct subscriptions need a narrowly scoped device credential and Convex authorization, or a subscription-capable relay that enforces the same boundary. Operator identity and permissions must be checked independently of the device identity. The owner must be able to see who requested an action and revoke access.

Commands should carry a unique ID, target device, operator, expiry and a restricted payload. A transactional claim prevents concurrent execution. Record acceptance and completion durably; after a crash, an ambiguous agent request must be reported for inspection, not replayed. Reconnects, subscription updates and duplicate delivery must never start a second turn. Keep an audit record and show status and errors to both operator and owner.

For an update, reuse the existing updater's release selection, verification and restart. Refuse or defer while exports or Drive uploads run; do not interrupt other active work silently. Persist the command before restarting, and report the installed version when the new process starts. Distinguish a downloaded update from a confirmed restart. A closed app cannot receive a command without an additional background service.

For an agent turn, require an exact project, explicit message and operator authorization. Preserve the owner's account permissions, project lock and existing conversation. The current agent path has no demonstrated enforceable monetary cap; keep remote paid work disabled until an enforceable limit and an accepted cost estimate exist. A command should not implicitly update, retry, change provider, open a project in the owner's window or start paid work on reconnection.

The receiver, relay and Convex functions all need implementation and offline tests for unauthorized access, revocation, duplicate delivery, crashes between claim and acknowledgement, expiry, project locks and update recovery. An owner must install a release containing the receiver before later updates can be initiated remotely. Publishing Convex functions and deploying the relay are separate rollout steps.
