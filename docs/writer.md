# How Script mode works

Script mode is Writer, merged into Edit on Oct 29 2026 (`docs/plans/2026-10-29-writer-into-edit.md` has the checklist): the script editor Repack's producers used beside Edit, now one app with it. Home has a **Scripts** tab beside Edits and Subtitled videos; `/scripts` is the library and `/scripts/<id>` a script. A script's **Start the edit** makes its Edit project from the script on this Mac and opens it (**Open the edit** after); an edit made from a script has a **Script** button back. This file is Writer's `docs/how-it-works.md`, brought up to date: what Script mode does is as Writer did it, and where it lives is Edit's.

**Where it lives.**

- `app/apps/server/src/writer/`: the server, ported from Writer's Rust (`src-tauri/src/`) to TypeScript. `index.ts` starts it with Edit's server, `routes.ts` is its whole HTTP API under `/api/writer/` (each route checked against what the person may do, `can.ts`), `store.ts` keeps scripts at `<home>/writer/scripts/<id>/script.json` beside their files, in Writer's own layout.
- `app/apps/web/src/writer/`: the UI, Writer's near word for word (`script-mode.tsx` is the screen; `api.ts` its calls).
- `app/packages/edit-types/src/writer.ts`: the types both share.
- `agent/writer/`: Repack's script guides and the team's house rules, word for word.
- `app/apps/server/test/writer/`: its tests.

**What's Edit's now.** Where both apps did the same job, Edit's (or the better of the two) does it for both: the sign-in and permissions (`accounts.ts`: Writer's capability ids, `scripts.*` and `review.*`, are Edit's now), Claude (the user's own Claude Code through the Agent SDK in Edit's server, `writer/claude.ts` over `claude.ts`: no sidecar), hearing (`transcribe.ts`), watching who speaks (`watch.ts`), YouTube downloads and captions (`youtube.ts`), research (`research.ts`), Drive and Google Docs (the team's Google sign-in in Settings, the same account Writer's relay held), the machine's id and name (`machine.ts`), logs (`diag.ts`: Script mode's lines are under `[writer]` in `logs/edit.log`), updates, settings and remote support (`edit remote diagnostics` lists the Mac's scripts; `edit remote resume <device> <script-id>` picks one up). The cloud is Edit's relay: `/v1/cloud/writer/*` (`apps/relay/src/writer_cloud.ts`) gives presigned URLs under `writer/` and calls the `writer:*`, review and footage-registry functions Writer used. Trello cards are still read through Writer's relay, which takes Edit's sign-in for `/v1/trello/card(s)` (`writer/trello.ts`).

**Writer beside it.** The data stayed where it was (Convex `writer:*`, R2 `writer/scripts/<id>/`, `writer/lessons.json`, the review links), so the old Writer app keeps working beside Edit until it's retired, on the same scripts. The first time Edit starts on a Mac it copies that Mac's Writer folder in (`~/Library/Application Support/com.spheceo.writer`, cloned: Writer's own copy stays): its scripts, lessons, cloud record (so nothing is pushed or pulled again), review notes and archive state.

## What Script mode does

Footage is cut on this Mac; every key (ElevenLabs, the YouTube proxy, Gemini) is on Edit's relay, so none sits in the app. Scripts are written the way Repack writes them: Opus reads the whole transcript with Repack's cut-in guide and judgment calls (`agent/writer/`), sends one plan of footage ranges and cut-in paragraphs, and the app checks it and cleans it up as Repack does (`writer/tidy.ts`): breathing room at clip edges, edges that run on into fillers or stop mid-sentence moved to where the thought ends, and pauses cut to a beat only where the footage's sound is quiet (a gap holding speech the transcript missed stays), never leaving a piece under 1.2 s (a lone "The" plays as a blip: its pause stays instead). A compilation outside 6 to 7 Letter pages (counted as Repack counts them, `writer/pages.ts`) or a FOIA cut under ten minutes goes back to Opus to bring in. It runs through the Claude Code login already on this Mac, so a build is paid by the Claude plan, not API calls. **Copy script** gives the text in Repack's Doc layout.

Every Repack format is covered, with Repack's own guides (`agent/writer/`, kept word for word; Edit's own rules from the team's reviews are `guides/house.md`, given after them to FOIA cases and non-courtroom compilations, and checked where a count can find them by `house.textFlags` and `plan.teamFlags`: full names, no addresses, outros of at most 45 words opening "In the end", cut-ins of 65, care words, the blow, narrated flashbacks, repeated transition openings, undated case openings, intro clips of 1–8 s that play again in the body, a case's first block of up to 2½ minutes) and wording (`writer/formats.ts`): **Interrogation**, **FOIA** (one-run or two-split opening, a dated case opening, a 10-minute floor), **Courtroom** (a two-paragraph opening, pacing that relaxes in the second half), and **compilations** of 2 to 20 videos, one case each, in either style (a title that opens with "When" is a standard compilation, any other a hidden one). The format is picked in **New script**, before the import starts: Interrogation, Bodycam or Courtroom (a compilation offers the compilation types the person may use). It stays visible in the project header; the chat builds in that saved format.

Compilation inputs accept mixed labeled or raw YouTube, Google Drive file/folder and Google Docs script links in case order; `(reuse)` / `[reuse]` annotations work alongside `REUSE`. A Drive folder stays one case, with all its recordings retained and joined into a full-size master for Edit. Reused scripts keep their complete original fetched text (ranges, link targets and finished cut-in words) in `reuses[].scriptText`, separately from transition context; `script` is the full Doc URL. Composite folder parts retain their folder URL and expose `mediaSource` / `originalKey` for the master. See `docs/compilation-import-review.md` for the handoff contract and review steps.

Split and Video playback show source-timed subtitles, including spelling corrections, toggled with **CC**; cut-in cards and source audition hide them. In Video view, drag either end of the timeline overview to zoom into a portion, its middle to pan, or double-click to fit. Zoom buttons and pinch/⌘-wheel still work.

**New script** takes what Repack's form takes: an optional **title** for a single video, as Repack's Working title (a YouTube or Drive link or a file on this Mac; left blank, the video's, folder's or file's own name; a Trello card fills in its name); an optional **article** about the case (read when the import starts, in place of searching); a compilation's videos **checked before anything downloads** (private, gone, live, age-restricted, over 10 hours), with **REUSE** before a link for a case the channel already covered (not imported: it takes only its transition, whose link goes into the Doc as a comment; **Reused cases** in Claude's panel can import its whole video later, joined onto the footage without encoding the rest again, transcribed alone, and read by Opus for its 5 to 8 strongest moments, which the build may open the video on as intro clips and nowhere else, `writer/reuse.ts`); a compilation's case given as the **Google Doc of a script the channel already made** (always a reused case: nothing in it is rewritten; Edit reads the Doc for its title, the footage under Assets, which **Reused cases** can bring in, and its narration, which the transition is written to lead into, `writer/reuse.ts`); several videos as **one Courtroom case** (a link's `t` kept as a hint to where the case starts); and a Drive case folder's **PDFs** (up to 20), which Haiku reads through Claude Code's Read tool for the case's facts (`writer/casefiles.ts`). An incident report among them stands in for the web search.

**Brief** in New script takes a producer's brief pasted as it came (`writer/brief.ts`): no two are laid out alike, so it's read roughly. The first line is the title; prose is the producer's notes, filed first among the research as "The producer's brief" (so no search runs, and **Research again** keeps them); each link is labelled by the line above it ending in a colon ("Part 3:", "Surveillance Footage:"), or by the words beside it, and given a role: **the case** (a hearing's "Part N", "Day N", trial, sentencing, or no label), **supporting footage** (surveillance, bodycam, an interrogation, a 911 call), **background** ("More on…", news, an explainer) or an **article** (any other web page, read for facts). Playlist and search parameters are dropped from YouTube links. The dialog shows how each link was read before anything downloads. One video imports as itself; several are one Courtroom case, joined hearing first by part, then supporting, then background, and each recording's label goes to the build beside its words ("the producer's brief: "Surveillance Footage": supporting footage, not the hearing: show it where the story reaches it…", `Script.labels`).

**Import from Trello** in New script lists the cards waiting on Repack's lists, read through the relay (which holds Repack's Trello key; nothing is written back) and parsed as Repack parses them (`writer/trello.ts`): **Raw Channels** ("Script (Sphe)": a case a card, its first Drive folder or video as the footage, its first other web page as the article, its name as the title; a card labelled "Missing footage" is passed over) and **Compilations** ("Ready for script (comp)": the YouTube, Drive and script Doc links from "case N" onwards, a link reused when its line or the line above says so, or when it's under a heading that does, "Reused:"). A card a script already has the name of is hidden. A reused video followed by the earlier compilation's card and its number there ("https://trello.com/c/U0FrQAUk (Case 4)", on its line or the next) becomes `REUSE <video> <card> case 4`: the check and the import follow that card to the script Doc attached to it (or linked in its description or comments), cut the case out of it (the Doc's cases lie between its rules, or a paragraph each after its "These were…" line; the case whose clip links name the reused video wins over a wrong number) and give its narration, as written, to the build for the transition, as for a Doc given as the case (`reuse.readEarlier`). The Doc's reuse comment names that script for the editor. An earlier script that can't be found leaves a plain reused case, with the reason in the check and the log. Picking one fills the dialog, and a compilation's links are checked at once.

Once a script is built, a message to Claude **revises** it, as Repack's chat editor does: Opus (since Oct 24 2026, as for builds) answers with targeted edits (trim, take out or insert words, split, move, delete, add or rewrite a cut-in, fix a spelling, tighten pauses, fix edges), which Edit checks and applies all or none (`writer/revise.ts`), with a repair turn for any it refuses. Asked to start over, Claude proposes it instead (`startOver`): the chat shows **Start the script over?** with Reject and Start over, and nothing is cleared until the producer accepts; then every clip and cut-in (or a commentary's draft) goes, the transcript, speakers, sources and research stay, and Versions keeps the script as it was (`reset_script_now`, `chat.askReset`). Web addresses in Claude's replies are links. A rewrite of narration already saved is a **proposal**, shown inline as removed and added words in Script view. An unscaled **Suggested changes** bar keeps **Follow up**, **Reject** and **Accept changes** visible above the page; accepting applies the proposals together only if the reviewed revision and original paragraphs still match. Reject keeps the saved wording. **Follow up** quotes the paragraph into chat. Chat follows new messages only while the reader is at the bottom, offers a jump to the latest, keeps unsent drafts per project, and has copy/retry actions and **Stop response** (ends the Agent SDK's turn). The conversation is kept with the script and goes back to Claude as context. Rebuilding from scratch is still there, behind a confirmation.

**Commentary** scripts are the other kind: an investigative video essay in the Internet Janitor's style (`agent/writer/commentary.md`), written from sources instead of one case's footage. **New script → Commentary** takes a title and, optionally, links; the first link is the brief. In the project, **Add** brings in more: a Google Doc, a Drive text file or a web page (shared with "Anyone with the link", or with Repack's Drive account), a text file on this Mac, pasted text, or the transcript of footage already in Edit. Each source is the **brief** (the angle and the evidence to use), **evidence** (what the script quotes), or **style** (a past script, for the voice; never quoted). Opus reads them all in full and writes the montage, the intro, numbered chapters and the ending, with every clip naming its recording and times, editor notes, and a list of checks before recording. Edit refuses a quote its source doesn't hold, a link no source gives, a clip cited from a style example, and a timed transcript's clip whose times don't match the words. Each project has a **pacing** for its builds: **Channel** (the channel's own clip-led videos: a line of setup, then the person talks) or **Documentary** (narration-led like Turkey Tom's: about three quarters narration, a short clip about every 30 to 40 seconds, and footage shown under the voice as "Show:" notes). With Documentary pacing, Edit sends a plan back when its narration share or clip count is far off. Narration, editor notes and paragraphs can be edited or removed; clips stay as checked. **Copy script** gives the channel's Doc layout, with a "Total time = …min vo + … = …min" line (narration at 150 words a minute), the recordings with their links, the sources and the checks.

**Comments** (`apps/web/src/writer/comments.tsx`) are the review's notes, one set shown both here and on feedback.spheceo.com, which is the standard: the Feedback tab (and the Review dialog) shows them as the page does (avatar, name, time, unread dot, #n per version, the words or General, the intent tag, a suggestion's old and new words, the page's state line from Queued to Done in vN with the fix's summary on hover, threaded replies, a ⋯ menu), filtered (All, Open, Done, Unread, Edit's, by person) and sorted (in order of the work, newest first). Selecting words in a commentary's narration offers Comment: the note goes to the review on those words (`reviews:note` with the page's `{kind: "text", blockId, start, end, quote}` anchor, an intent, a suggestion's replacement), named in the text the version was shared with (`review-text.json`, kept at each share or read back from the version's snapshot). Replies go up signed with the person's name (`reviews:reply`), and Edit's own notes can be deleted (`reviews:deleteNote`). A comment's words are soft yellow, brighter while it or its card is hovered or open; clicking them opens the card. Unread is kept per Mac, as the page keeps it per browser.

**Feedback** teaches Claude what reviewers noted on a commentary, and tests that it learned it (`writer/feedback.ts`, `apps/web/src/writer/feedback-panel.tsx`). Since Oct 24 2026 the feedback is the notes on the script's review page (feedback.spheceo.com, `writer/reviews.ts`): each reviewer's note with the words it's on and its replies, a suggestion as its replacement, and notes left from the Feedback tab itself (posted to the review as Edit's, `reviews:note`, so they show on the page too). **Teach from these notes** reads them (polling the page first) and finds each in the script. Any item can be left out, and a highlight without a comment can be given a note saying what's wrong. **Run round** then:

1. Makes the answer key (first round only): Opus applies the feedback directly.
2. Writes the lesson (when there's none): Opus turns the feedback into a skill in general terms. A lesson that copies six words in a row from the script, or uses a name only the script has, is sent back; it would show the round the answers.
3. Tests it: a fresh Opus gets the sources, the script and the lesson, never the feedback, and is told only that a reviewer found problems of those kinds.
4. Grades the round: Opus compares what changed, paragraph by paragraph, with the feedback and the key. Each item is fixed, partly, missed or wrong, and every change nobody asked for is marked harmless or harmful. The match counts fixed as 1 and partly as a half.

**Improve the lesson** has Opus rewrite it from the last round's misses, or the producer edits it by hand; then run another round. **Keep the lesson** adds it to the lessons every commentary build reads, after the guide (kept in `lessons.json` beside `scripts/` and synced as `writer/lessons.json` on R2: every Mac merges its lessons with the cloud's by ID, and a lesson forgotten on one Mac is forgotten on all). **Use this round's script** makes a round's script the script, with what it didn't fix applied directly. Pulling again starts over. Everything else is under the script's `feedback/` folder, so it syncs with the script. A round takes about 15 minutes; the first, which also makes the key and the lesson, takes longer.

**Review** shares a script on a Repack link (`writer/reviews.ts`, `apps/web/src/writer/review.tsx`): anyone with it reads the script and leaves notes under a name, no account. The page shows the script as blocks whose IDs stay as it is edited (`writer/blocks.ts`): each footage clip (its range and words), each cut-in's narration, a commentary's montage, headings and paragraphs. **Share again** publishes the next version on the same link. While Edit runs it asks Repack for changed notes every 45 seconds; scripts with open notes get a count on their row and on the Review button. When a reviewer clicks **Ready for changes** on the review page, the one computer an admin chose on accounts.spheceo.com's Fixing page fixes them: Edit checks in there (`reviews:checkIn`, every 45 seconds, every 15 on the fixing computer, with the Mac's hashed hardware id from `machine.ts`, shared with Edit), takes the request (`reviews:takeFix`), claims the open notes (`reviews:claim`, so no note is fixed twice) and fixes them one at a time (`writer/fixing.ts`), the page following along (`reviews:fixProgress`), then shares the next version, which the page offers to switch to: a footage script with the chat's edits, saved narration written straight in; a commentary with edits to the paragraphs the note is about, so nothing else can change. What each note changed is measured word by word on the blocks and sent back with Claude's summary; the page and Edit's Script view show it as green bands, and hovering one shows the reviewer's words, their name, Claude's summary and the version it lands in. A note Claude made no change for gets its reason as a reply and stays open; one a reviewer opens again is fixed again. Nothing is fixed by itself otherwise (the five-minute quiet timer and its switch went on Oct 24 2026); the Review dialog fixes the open notes now, by hand, on any computer. **Approve vN** marks the latest version done: the link takes no more notes, nothing is fixed by itself, and Repack deletes the other versions' review files (every note from every round stays; Edit's own version history is separate and untouched). An approval made on Repack's page is heard on the poll (`reviews:open`); the row and the Review button show "Approved vN". Sharing again starts the next version, unapproved; an approval can be taken back.

The review page (feedback.spheceo.com, spec v2) gets more than the text: each footage block's transcript just outside it (for "start earlier" / "end later"), where it plays in the preview and each word's timing, narration's read time at 150 words a minute, every block's running time, its `edit:` notes, an outline rail (opening, cases or recordings, ending; a commentary's sections), the format's target length, and the preview's key. Word timings move to a file of their own if the page's data would pass Repack's 512 KB. What a reviewer says exactly is done exactly, with no model in between: a suggestion's words replace the anchored ones (on a footage clip, as a respelling, word for word), a footage action cuts the chosen words or moves the clip's edge to the words chosen beside it, and a note for the editor becomes an `edit:` note as written. A note's intent limits what Claude may change: a question is only answered, a fact is checked and answered with its source (edited only if wrong), wording changes narration only and a cut footage only (a fix that strays is undone and the note stays open), FYI changes nothing. "Everywhere" carries the ask across the script.

**Make this v1** (the Review dialog, once a link is past v1; `POST /api/scripts/<id>/review/compress`): the script as it is now becomes the link's only version, v1, on the same link, through Repack's `reviews:compress` (allowed on the relay with `review.share`). The later versions leave the link, their files are deleted unless v1 still uses them, and every note moves onto v1. Edit's own version history is untouched. A commentary's page shows its montage under the Intro heading, as the team's Docs do.

**edit: notes** are for the video editor: asked for one ("add an edit note: a blue waveform for this 911 call"), Claude puts it on that footage clip's timestamp, or under a commentary paragraph's editor note, starting `edit:`. They show in purple beside the page, go into the Google Doc, sync with the script, and Edit's agent follows them in that section when the script is handed over. On a written commentary, a message now changes only the paragraphs it is about; **Rewrite the whole script** under the box writes it again from the sources.

**Clips → Find clips** searches YouTube for what a commentary brief asks for (`writer/scout.ts`). Opus turns the brief into up to 30 moments the video needs, each with a few searches; yt-dlp runs them and Sonnet picks up to three likely videos a moment (the original stream or podcast first), and the brief's own YouTube links are always read. yt-dlp fetches each video's English captions, timed to the word, without the video; Sonnet reads them for the moments and copies their words, and Edit keeps only those whose words are in the captions near their times. Where a moment's point is what's on screen, Edit downloads just those seconds at 360p, tiles 12 frames into one image, and Sonnet says whether it shows what's wanted. Each video with a moment goes in as timed evidence holding its captions around each moment, so the next build can play its clips; a second search replaces those sources. The Clips tab lists them by the brief's chapters, with each video's link at the moment, the words, why it fits and the frames. A search takes 10 to 20 minutes; videos without English captions are passed over.

Before writing, a build:

- **Names the speakers** with Haiku through the Claude CLI, as Repack's speaker check does: "Name (Role)" only when a full name is stated, otherwise the role. It also runs right after transcription.

**Courtroom footage on YouTube is read from YouTube's own captions** (`writer/captions.ts`), not heard: free, and minutes for a hearing of many hours. Only YouTube's English speech recognition counts (the `en-orig` track; a translation, or captions an uploader timed by line, don't), read with the person's YouTube sign-in when there is one; a transcript Edit already heard wins, and a video without captions is heard as before. A word has a start but no end, so it ends after the time it takes to say (60 ms a letter, 250 ms a digit: the 75th percentile of 89k words ElevenLabs timed in Edit's scripts) or at the next word, whichever comes first. YouTube marks a change of speaker with ">>" but never says who, so each ">>" opens a turn of its own. Measured on Oct 25 2026 against ElevenLabs on a 20-minute hearing (3,042 words matched): starts within 49 ms (110 ms for nine words in ten), ends 58 ms late (140 ms), where the next word's start would be 373 ms; 93% of the marks fall on a change of speaker, but they mark only about two thirds of them. The captions are kept as `captions.json`, never as the recording's `transcript.json`, so they're never handed to Edit as heard words.

Words from captions get **who says each line read from the conversation** (`writer/caption_turns.ts`), as Repack's line check reads them, in place of the watcher: Sonnet reads lines from across the footage with the case's names and the producer's notes and lists who speaks ("Name (Role)", or the role), then reads the transcript 120 lines at a time, four at once, each window a few lines into the last, and gives every line to someone, splits a line where a second person starts (quoting their first words), and respells a name YouTube misheard. Lines end at a turn, a pause of 1.5 s or 45 words. Each answer is kept under `turns/`, with the words as captioned (`turns/heard.json`), so **Retry unfinished speaker checks** reads only what wasn't answered.

Once a captioned script's build has chosen its clips, **its footage is heard exactly** (`writer/exact.ts`): Scribe hears only those stretches (each clip with 3 s either side, neighbours joined, in pieces of one request each: about 25 minutes of a 9-hour hearing), so each word there takes Scribe's start, end and spelling (a short run each heard differently, word for word, takes Scribe's words; any other word sits between its neighbours, and every word keeps its ID). Sonnet then reads those stretches' lines, broken wherever Scribe heard the voice change, with the cast, and gives every line its person. The same plan is cut again on the exact times, and a piece with nothing above a fifth of the speech level of the minute around it is dropped. Footage cleared from this Mac is brought back first; if the hearing fails, the build keeps the captions' cut and its report says so. The stretches heard are kept in `Script.exact` (and what Scribe heard in `exact/`), so a revision hears only footage it newly plays; `POST /api/scripts/{id}/exact` does it for a script built before.

Right after transcription, every other import also **checks who speaks** by watching the footage, as Repack's and Edit's watcher does: Gemini (through the relay) sees and hears about four minutes at a time, eight stretches at once, and says who says each line and who each person is. Speech to text tells voices apart by sound alone, so this splits two detectives it heard as one and joins one person it heard as two; a guess changes nothing. Each person gets "Name (Role)" when the footage gives a full name, otherwise the role; then Haiku reads the corrected transcript for the suspects, the voices the footage didn't show, and a full name the title or transcript gives someone the footage only gave a role. Each stretch's answer is kept, so a retry doesn't pay twice (about $0.50 an hour of footage). Audio has nothing to watch, and a failure is a note on the script: the speakers stay as heard and Haiku names them as before.

Once who speaks is settled (read from captions, watched, or named), **words that spilled across a change of speaker go back to who said them** (`writer/spills.ts`, Edit's `turns.ts`, from Repack's): at a change of speaker a word or a few often land with the wrong person ("…when investigators questioned / him after this incident" on the sergeant). Gemini, through the relay, reads each recording's turns 120 at a time, its pauses marked and a long turn shown by its two ends, and names the words to move and which way; a move is made only when those are the very words at that edge (at most 12), so nothing is added, dropped or reworded. It runs at the end of an import, after Retry unfinished speaker checks, and over the stretches the exact hearing just heard. Each answer is kept under `spills/`, so a turn asked about once is never paid for again; without an answer the words stay as they were. A long file's whole-file hearing, used only to tell its voices apart, is asked without the case's names (they cost a fifth more; the pieces still spell them).
- **Researches the case for free**, the way Edit mode does: Haiku writes a few searches, Edit reads DuckDuckGo's plain HTML results and the pages on this Mac's own connection (no search API or key), and Sonnet keeps only the reports about this case with their facts (dates, places, names, charges, outcomes). They go to the builder as RESEARCH. **Research again** in the script looks once more. A failed search never stops a build. A compilation's cases are researched each on its own, side by side, from its own video's words, and each report is labelled with its video (`research.find`). Reading only the start of the transcript found reports about the first case alone.

**Google Doc** exports a script as Repack does (`apps/web/src/server/script-documents.ts`): a new Doc each time, made from a Word file Edit lays out (`apps/web/src/writer/doc-export.ts`, `apps/web/src/writer/docx.ts`) so Docs keeps its comments, in the "Writer scripts" folder of the account that owns Repack's script Docs, open to anyone with the link as an editor. It lists the footage under Assets (a compilation's or a Courtroom case's videos in order), and every timestamp links to its own video's moment where there is one and carries a comment (a footage script's first and last words; a commentary clip's quote and what to verify), narration words to blur get Repack's "Note to editor: Blur this" (a commentary's get "Censor", and its editor notes become comments), all signed GeniusScriptwriter10. **Export draft** makes the same Doc named "(DRAFT) …" without replacing the script's Doc; the dialog says when the script has changed since the last export, lists every export (from Drive, trashed ones marked), and reads back the comments people left on the latest Doc. A commentary can be rewritten with the open ones. Edit makes the Docs with the team's Google sign-in (`writer/docs.ts`), never through a key in the app.

Editing has undo and redo (⌘Z, ⇧⌘Z), 30 steps, including undoing a fresh build. Edits show at once and save in turn; one refused because the script changed elsewhere takes the script from disk. **Versions** keeps every save (one author's edits within ten minutes merged), says who made each and what changed, and restores one. Clips move by dragging on the timeline; transcript words go in at the playhead as an insert edit, or at the start, and a word can be respelled. A Courtroom script's Script view drops the blank lines between blocks after the first, as Repack's does (the Doc runs them on in one paragraph). The heading can be rewritten in the Script view, and a comment written on a timestamp there goes into the Doc on that timestamp. Selecting narration offers **Add comment** and **Add to chat**: a comment keeps the selected words with it, syncs with the script, is read by the agent and exports on those words in the Doc; chat receives the quoted passage and its paragraph. The document toolbar shows **Fit page**, **Fit width** or the chosen percentage; comment cards stay at their normal size while the paper zooms. The Script view omits the Assets list, and **Google Doc** is in the project’s ⋯ menu. A build's outcome is kept beside the script, so one that ended unwatched, or one Edit closed on, says so.

**Archived** scripts (`writer/archive.ts`): Repack's page can archive a script to free space; its server deletes the footage on R2 and marks the script's Convex row. When Edit hears it, it deletes the script's footage here too (originals, the preview, Drive recordings, reused cases' videos, heard audio) and keeps the script, its transcripts, the watcher's answers, versions, chat and every other small file, so it lists and reads, read-only, as Archived. A file from the Mac's disk outside Edit's folder is never touched. **Restore footage** (or Restore on Repack's page) downloads the footage again, from Edit's originals where they're back, else from the recordings' YouTube and Drive links, rebuilds the preview, puts it back in the footage registry and tells Repack (`writer:clearRestore`); the transcripts were kept, so nothing is heard again. What came from the Mac's disk can't come back and is listed as missing.

Every script is in the cloud with its footage: each recording goes to Edit's footage registry on import (Drive, YouTube, and a file from disk as `sha256:<hex>`). Scripts from before are brought in by a backfill, one at a time in the background (`cloud/backfill.json` says what it did); a YouTube video Edit downloaded before it used Edit's format is downloaded again in it first (at most one a quarter hour) and replaces Edit's older copy in the registry. Scripts titled "TEST…", commentaries and unfinished imports are passed over.

## Imports

Footage comes from three places, as in Repack:

- **YouTube.** `yt-dlp` downloads on this Mac's own connection, which costs nothing. The relay's DataImpulse proxy (Repack's `PROXY_URL`) takes over only for a busy hour (4 or more YouTube downloads in the last hour, as a 20-video compilation would be) or when YouTube blocks this Mac; each try gets a fresh sticky exit. The proxy's login reaches the Mac only for the length of a download.
- **Google Drive.** A file link, or a folder link for a case: every video and audio recording in the folder and its subfolders, in name order, joined into one timeline as Repack joins them. Edit reads them as the Drive account Repack imports with: the team's Google sign-in in Edit's Settings (`writer/drive.ts`, `library.accessToken()`). Share footage with that account. Downloads come straight from Google.
- **This Mac.** The file stays where it is.
- **A compilation.** 2 to 12 YouTube or Drive video links, one case each, joined in order with a "Video N" header per case.

Work runs side by side: up to 3 imports at once, 3 recordings downloading at once (Drive folders and compilations), and 4 transcription pieces heard at once (the relay allows 60 requests a minute per Mac, as Edit's does). Speaker checks watch up to 8 stretches at once. A gateway or connection timeout splits that stretch into smaller ones; each smaller answer and the split are kept for a retry too. Each parent stretch has a six-minute deadline and at most nine requests across retries and splits. The original transcription is saved before speaker corrections, so a retry keeps the same windows and cache keys. **Retry unfinished speaker checks**, in the warning or the project’s ⋯ menu, reuses completed answers and asks only for unfinished work. Opening, polling and reconnecting never start that retry. Progress starts with the saved checks already counted and says how many it reused.

Import completion refreshes the open script even though importing does not make an edit revision, including when the window returns after sleep, and shows an **Import finished** notice. Joined footage keeps a marker and title for each recording inside its timeline clips, including older imports whose footage is one long clip. The import screen separates transcription, visual speaker checks and naming the speakers. An unfinished visual check leaves the transcript and its audio-based speaker labels available; those labels may still combine or split voices incorrectly. Its saved status keeps unverified stretches visible until a check finishes.

**Complete transcription** in a footage project's ⋯ menu also works on an existing project with only some words. It runs in the background, keeps the saved words and their spelling corrections, cuts and narration, and fills missing speech from each recording. YouTube recordings try available English captions first (original word-timed captions, other word-timed English tracks, then manual or automatic cues), then read who speaks from the conversation (`writer/captions.ts`, `writer/caption_turns.ts`), including older audio imports whose visual speaker checks did not finish. Captions and completed audio hearings are cached separately; missing captions fall back to a completed local or shared hearing, then audio transcription. Manual cues receive estimated word times within their duration; chosen footage is still heard exactly before it is cut. Word matching preserves saved IDs and corrections while filling even short gaps, including multiword corrections. Caption recovery needs no local footage download. Newly brought-in reused YouTube cases take the same captions-first path, and those new captions get a speaker-label pass; words, corrections, cuts and speaker labels already saved stay as they are. Their cached transcription is reused by later completion jobs. Caption speaker failures keep a retry action, and superseded visual warnings go away. Opening a project never starts this work by itself.

When an import goes wrong it stops in a state you can act on, as in Repack:

- **Retry** carries on from where it stopped. The YouTube download (its `.part` too), each Drive recording, the preview and each completed transcription answer are kept and reused. If the connection drops before an answer arrives, that request may already have been charged; manually retrying may charge it again. Edit stops rather than automatically resending an ambiguous paid request, shows a short recovery message, and keeps the transport details in Logs on the importing Mac. An import that stopped because Edit closed, or that hit a bug, is retried the same way.
- **Needs your choice** pauses an import on a question instead of failing it: some of a folder's recordings didn't come through (go on without them, retry them, or cancel); a folder holds more than an import takes (60 recordings, 20 hours, 10 hours or 30 GB a file: choose which); or no words were heard (open it without a transcript).
- A recording cut short (an interrupted upload) imports what it holds, and the script says so. One that downloads short is fetched again once from where it stopped, then dropped so a retry starts it clean.
- A YouTube bot check or dropped connection with nothing downloaded yet gets one more try, on a fresh proxy exit when there is one.
- Transcription retries only what can't have been billed: the relay unreachable, or busy (after 30 s, then 60 s). Refusals (no credit, a wrong token) say what the relay said and stop.
- Claude busy or overloaded gets one more try a minute later; a plan it sends wrong, or no plan, gets up to two repair turns on the same session. Nothing is saved to the script until a plan passes.
- Edit's own setup check covers Claude Code, ffmpeg and ffprobe, yt-dlp and the relay.

Every import makes a 480p preview (a joined folder's footage is that preview). When there are several recordings, each one's piece of the preview is encoded in its download's lane as soon as it lands, while the rest still come down, and the pieces are then copied end to end in seconds (`imports.encodePiece`, `media.append`). A missing or mismatched piece means the whole preview is encoded, as before. A single video's preview, and each piece, is decoded, fitted and encoded on the Mac's video hardware (`h264_videotoolbox`, `media.joinOne`): with three downloads' pieces at once it's a third quicker and takes a fifth of the processor, at close to libx264's picture (SSIM 0.980 against 0.987) and size. Footage the hardware can't decode (AV1 on an M1), or a Mac without it, is encoded by libx264 instead. Pieces from the two encoders are never copied together (`media.formatOf` reads the encoder), and a reused case's video is encoded as the preview it joins was (`media.joinLike`). A single YouTube video's preview isn't encoded at all when YouTube has a 480p H.264 picture of it (`youtube::PREVIEW`, most do): that picture comes down beside the video (`Pace::Preview`, the same routes, a fifth of the bytes or less) and is copied with the video's sound (`media.copyPreview`, under a second for half an hour); without one, or if the copy doesn't fit, the preview is encoded. A compilation's pieces aren't copied from YouTube: its 480p files differ in their stream headers from video to video, so they wouldn't copy together. The preview is made beside the words (`imports.pipeline`, `Pending`): transcription reads the recordings themselves, so it starts as soon as the footage is down, and the speaker checks and spilled words follow while the preview is still being made. Only the watcher on a joined case (whose footage is its preview) and a recording heard from the preview wait for it; the script is ready once the preview is, written to `.proxy-making.mp4` until it's whole, and a joined case's overview is drawn from it last. Titles the link check read are reused by the import instead of asked for again and is transcribed through the relay. The editors play it as Repack plays its footage, never waiting on a download: `preview://localhost/<id>` (`writer/routes.ts`) answers each range from the file on this Mac when it's here, otherwise from the cloud's copy through a presigned URL (kept, and asked again after 40 minutes), from 2 MB blocks kept in memory (96 MB) with the next four fetched alongside, since WebKit reads a video's index a few bytes at a time (a long compilation's is 19 MB) and wants every range with an end answered in full (open-ended ones get at most 4 MB); the script's kind is checked once per change of its script.json, not on every range (`can.requireId`). A preview played from the cloud is brought down behind it (`routes.keepHere`), so a cut's jumps around the footage turn instant once it's here. The local API's `/api/scripts/<id>/proxy` does the same. Previews are made with the index first (`+faststart`), so playing starts after the first range and a jump is one more. So a sync never downloads footage: a Mac's first sync brings each script's small files (script, transcript, peaks, chat, versions) and leaves its preview and originals in the cloud (`writer/cloud.ts` pull, recorded in `cloud/storage.json` as cleared footage is), and the list fills in at once; only joining reused cases onto a preview brings it down (`cloud.fetchPreview`).

Builds and imports run on this Mac, not in the browser. A build is a background job the page checks every few seconds, so a dropped connection, a sleeping laptop or a reload does not lose it, and the open script is in the URL. Over plain `http` the browser has no Clipboard API; **Copy script** falls back to the older copy command.

## Hearing, and the footage shared with Edit mode

Footage is heard as Edit hears it, one system for both modes (`writer/hearing.ts`, a port of Edit's `transcribe.ts`): a recording up to 90 s in one go; a longer one twice at once, in 40 s pieces (4 s either side) for its words and times, and whole for who speaks, the two lined up by what they say. A joined case is heard recording by recording, from each one's own file (joined cases now keep their recordings). Every request listens for the case's names (`writer/names.ts`, Edit's `names.ts`: Gemini lists the people and places its articles, case files and narration give, each word checked against them, surnames on their own too); case PDFs are read before the footage is heard, so their names count. What's heard is kept as it comes in, so a retry never pays twice; each recording's transcript is `transcript/<recording>/transcript.json` in Edit's format.

**Sharing with Edit mode** (`writer/handoff.ts`): after every import, each recording goes to Edit's footage registry (`edit:putMedia`, under `drive:<id>`, `youtube:<id>` or `sha256:<hex>`) with its original on R2 under `edit/originals/`, and its words, with the voices the watcher and naming settled, to `edit/analysis/<source>/transcript.json` in Edit's format; before hearing a recording, Script mode reads Edit's transcript of it if there is one. So an edit made from the script neither downloads nor hears it again. What is in Edit's originals (`edit-shared.json` beside the script) leaves the script's own sync. YouTube videos are downloaded in Edit's format (H.264 up to 1080p), so both modes share one file (hard-linked where they can be).

## Cloud

Every script is in the cloud and on every Mac running Edit, as Edit's projects are. Each script's body (`script.json`) and files (the proxy, the original, transcript pieces, sources, research, the watcher's answers) sit on Cloudflare R2 under `writer/scripts/<id>/` in Repack's bucket; Convex (Repack's deployment, `apps/web/convex/writer.ts` in the Repack repo, published with Repack's `db:push`) keeps the index: each script's rev, body and files. Edit only talks to the relay.

`writer/cloud.ts` runs in the background whenever someone is signed in. Saves land on disk as always; a few seconds after a script is still, its changed files go up, then a new body, then `writer:commitScript` naming the rev it began from. Every 30 seconds it pulls what other Macs pushed. A commit another Mac overtook is refused, and this Mac's version is kept as "<title> (conflicted copy)" before the cloud's is taken. Scripts still importing or being written by Claude wait until they are done. Deleting a script marks it deleted in Convex (so every Mac removes it) and deletes its files from R2. What this Mac knows is in `cloud/ledger.json` beside `scripts/`; deletions waiting for the connection in `cloud/deleted.json`. The lists and editors show the state (synced, uploading, offline), and an open script follows changes that come down.

A script the cloud refuses (its commit or a file turned away, not just offline) waits, longer each time, while the rest sync; the list shows it as **Not in the cloud** with what the cloud said (`cloud.refused`, `Summary.cloudRefused`), since nobody else can open it until it's up (Edit's Home does the same, after a teammate's import never reached the cloud on Oct 29 2026).

The bodies are on R2, not in Convex's file storage: Edit's nightly sweep deletes Convex-stored JSON that no Edit project uses. Keep Script mode's keys under `writer/`: Repack's own cleanup deletes unrecorded files under `repack/`.

## What isn't here

- **Live sync of a script and its edit.** Start the edit and the Script button link the two; a change saved in one doesn't yet change the other (re-voicing just the sentence edited, a clip added in the script showing in the edit, one undo for both). That's the next step of the merge (the plan's last line).
- **Clearing a script's local footage** (Writer's `storage.rs`, Settings → Storage) and its **backfill** of old scripts into Edit's registry (every script made since does it on import) didn't come over; `distill.rs`, a developer's test tool, was dropped.
- **Writer's own relay** still serves old Writer and Trello; Edit's relay serves Script mode's cloud once it's deployed with `writer_cloud.ts`.
